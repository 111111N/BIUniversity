# Сравнение учебных справочников и расписания — G03

В проверке резервной копии отдельно сравниваются 18 коллекций из восьми сохранённых документов:

- аудитории и история их карточек;
- именованные шаблоны и история;
- неизменяемые версии публикаций расписания с полным снимком недели;
- общие учебные годы, семестры и история;
- программы, формы обучения и история;
- версии учебных планов, назначения планов группам и общая история;
- календари групп и история;
- назначения преподавателей по типам/периодам и история.

Каждый источник сначала проходит собственный полный строгий декодер. Повтор ключа, неподдерживаемая версия, повреждённая схема или противоречивая история дают отдельный несравнённый документ; источник не считается пустым. Декодированные документы переиспользуются внутри сравнения карточек и истории. Общие бюджеты текста/записей, отмена и контроль исходного снимка сохраняются.

Карточки, события и публикации адресуются собственным ID в конкретной коллекции и ключе документа. Назначение плана имеет ключ сохранённого ID группы; отдельный ID из имени группы не генерируется. Вложенные строки плана, часы, снимки периодов, оснащение, списки типов и полная неделя входят в сравнение содержимого. Одинаковое число элементов не скрывает различия. Документные ревизии, порядок массивов и прочие метаданные дополнительно остаются в общем сравнении исходных ключей.

Для каждого раздела доступны счётчики, поиск/фильтры и страницы по 20 различий. В отчёт попадают ID и названия изменённых полей; значения, имена, причины и вложенные снимки не копируются в технический отчёт. Скачивание проверяет полноту каждого нового раздела и его версию, включая счётчики, уникальность и адреса записей. Для старого отчёта без новых разделов нужна повторная проверка файла.

Полные значения различающегося ID открываются только через существующий авторизованный просмотр: проверяются SHA-256 исходного файла, учётка, полный снимок localStorage, наличие различия в привязанном результате и поддерживаемая схема. Только после полного просмотра можно сохранить черновой выбор версии. Непоказанные дополнительные поля и превышение размера просмотра не дают выбрать неполную версию. Поздний ответ, смена источников, доступа, файла или черновика выбора делают результат неактуальным. Локальные события всех новых справочников также инвалидируют открытый просмотр.

## Выбранные общие учебные периоды

В разделе учебных справочников есть отдельная проверка выбранных лет, семестров и событий истории. Совпадающие записи берутся один раз; сохраняются записи только из архива и только из браузера. Различающиеся ID требуют выбора после просмотра. Повторный, лишний или уже не относящийся к конфликту выбор отклоняется. Полный кандидат проходит строгий декодер: даты, связи года/семестра, уникальность, последовательные ревизии и итоговые карточки должны совпадать с историей.

Снимки периодов хранят глобальную `catalogRevision`, соответствующую позиции события. Поэтому проверка не сортирует и не объединяет независимые ветви истории. Выбранная полная история должна совпадать с одним из источников и сохранять глобальные позиции всех общих сохранённых событий. Совместимое продолжение истории поддерживается; ветви с уникальными событиями с обеих сторон или переупорядоченными общими событиями блокируются. Записи только из браузера не выбрасываются ради совпадения. Это проверка совместимости существующего хода истории, а не новая миграция ревизий.

Проверка выбранных аттестаций использует тот же выбор периодов. Каждый снимок сверяется с точной глобальной ревизией и временем создания ведомости. Различие документов периодов само по себе больше не является безусловной блокировкой: нужен согласованный выбранный набор. Отсутствующий/повреждённый источник, нерешённые конфликты, несовместимая история и отсутствующая точная версия остаются блокировками. Кандидат периода остаётся внутри доменного слоя; UI получает только статус, счётчики и сообщения.

## Выбранные карточки и полная история

Отдельная проверка собирает кандидаты шести документов: программ/форм, планов/назначений групп, календарей групп, преподавательских назначений, аудиторий и шаблонов. Коллекции и правила идентификации задаются в общем реестре, сама проверка переиспользует один механизм. Кандидат сохраняет записи только из обоих источников, требует явного выбора каждого конфликта и проходит полный исходный декодер. Карточки и их ревизии должны совпасть с воспроизведённой историей. Выбранные состояния закрытия, архивирования и публикации не изменяются автоматически.

Проверка не синтезирует новую историю: выбранные события должны составить полную историю одного источника без изменения позиций общих сохранённых событий. Расходящиеся ветви, недостающий выбор и несовместимые карточки блокируются. Метаданные берутся только из подтверждённого источника этой истории; ревизии и ID не перенумеровываются. Отсутствующий в обоих источниках документ получает отдельный статус, а не превращается в пустой кандидат. Эти проверки создают только временные объекты внутри доменного слоя.

После структуры проверяются зависимости выбранных кандидатов. Существующие строгие инспекторы получают выбранные программы/формы, планы, календари, назначения, аудитории, шаблоны и согласованный выбор общих периодов. Проверяются сохранённые версии, снимки программ/форм и семестров, ссылки на точные публикации и версии аудиторий/назначений, наличие авторов и связи с учебными справочниками. Для событий смешанного набора граница времени — момент текущей проверки, а не дата старого архивного файла: выбранные записи браузера могут быть новее архива.

Базовые учётки/люди, группы, дисциплины и расписание проходят отдельную проверку соответствия полному сохранённому источнику. Она учитывает выбор карточек, событий обучения/истории людей, пар и публикаций; адрес связи журнала включает дисциплину и группу. Сохраняются все записи только из одного источника. Принятый документ должен целиком содержать выбранный набор; смешанный кандидат не собирается. Его ревизия не может быть ниже другого источника. Общие неизменённые события сохраняют позиции. Если подходят обе версии, но полные документы различаются, источник остаётся неопределённым.

Служебные поля, граница старой истории, версия формата, счётчики, квитанции импорта/массовых действий и метаданные недель должны совпадать между источниками. Их конфликт не разрешается выбором отдельной карточки. Разница таких полей, неоднозначный/повреждённый ключ, лишний выбор и превышение общего бюджета блокируют проверку; другой источник не подставляется вместо ошибки. Кандидаты передаются поддерживаемым проверкам зависимостей только после подтверждения полного источника. Статус `matched` означает соответствие сохранённому документу и его действующему декодеру, а не новую проверку полноты ранней истории или разрешение восстановления.

Выбор версий людей и их истории доступен после просмотра через ту же проверку полномочий и снимка, что и для учёток. UI получает только четыре кратких результата базовых источников и причины блокировки. Исторические полномочия, программа группы и снимки дисциплин остаются неподтверждёнными там, где нет достаточного источника. Ошибки и неподтверждённые связи показаны отдельно с фильтром и страницами по 20 замечаний.

Структурный статус каждого документа и статус его зависимостей различаются. Согласованные собственные карточки/история не разрешают применение, если зависимости или полномочия не подтверждены. Файл, автор, снимок localStorage и ревизия выбора проверяются заново после всей асинхронной операции. UI получает только статусы, счётчики и замечания, без документов-кандидатов.

## Связи выбранных базовых источников

После подтверждения полных источников проверяются ссылки между учётками, группами, дисциплинами и расписанием. Учитываются текущие назначения и группа студента, прежние/новые назначения аудита, состояния до/после события обучения, авторы истории людей/учёток/групп/дисциплин, преподаватели и группы пар, связи журнала и публикации. Встроенные группы и имена не заменяют сохранённый ID. Отсутствующая запись в известном полном источнике — ошибка; отсутствующий или несогласованный источник оставляет ссылку неподтверждённой. Внутренние связи человека и учёток продолжают проверяться строгим декодером учёток; повторная миграция людей не выполняется.

Для выбранных документов переиспользуются проверки номеров зачёток, истории выдачи, квитанций импорта/массовых действий, состояний архивных групп, архивных публикаций и пересечений расписания. Граница будущих пар берётся на момент текущей проверки по действующему московскому правилу окончания занятия. Прошедшая публикация сама по себе не блокирует архивированную группу. Будущая дата занятия разрешена; время сохранения карточки/события/недели после момента проверки является ошибкой.

Текущая роль, блокировка входа или переименование не используются как доказательство исторических ролей и полномочий. Для старого реестра без людей и ранних снимков дисциплин сохраняются отдельные неподтверждённые сведения. Полный итог замечаний ограничен 25 000 записями и общим текстовым бюджетом; при превышении возвращается ошибка всей операции, а не частичный успешный результат. Проверка остаётся отменяемой, привязанной к снимку и без записи в хранилища.

## Ссылки аттестаций на полные источники

Проверка выбранных аттестаций использует тот же механизм полных базовых источников для людей/учёток, групп и дисциплин. Выбор карточки не обходит конфликт истории, служебных полей, счётчиков, формата или ревизии документа. В проверку передаётся весь подтверждённый просмотром выбор этих источников, включая людей и события истории, а не только карточки, на которые ссылается ведомость. При передаче старого интерфейса выбора отдельных карточек они также проверяются через полный источник; более слабого обходного пути нет. Одновременный выбор карточек и полный выбор должны совпадать.

Ссылки на студентов, научных руководителей, преподавателей, членов/председателей комиссии, авторов событий, исправлений и публикаций считаются найденными только в соответствующем полном документе. Неопределённый источник оставляет ссылки неподтверждёнными; повреждённый или отсутствующий — недоступными. Причины и краткие результаты источников показаны прямо под результатом проверки аттестаций. Снимки учебных периодов по-прежнему сверяются с выбранной полной историей периодов и точной глобальной ревизией.

Замечания имеют собственный поиск, фильтр источника и страницы по 20 строк. Разные причины для одного ID сохраняются отдельно, без подмены сообщения ключом общего списка различий. Общие бюджеты и отмена остаются обязательными; превышение не возвращает частичный успешный итог. Наличие ID не подтверждает историческую роль, состав на дату сдачи или право на восстановление. Документы-кандидаты и значения полей не попадают в UI/отчёт; хранилища не изменяются.

## Согласованность снимков истории групп

Исходный архив и выбранный полный источник групп проходят общую проверку сохранённых состояний до/после событий. Проверяются непрерывность известных снимков, совпадение последнего известного состояния с карточкой, автор/время начала фиксации и время последнего изменения. Архивирование и восстановление должны менять только состояние архива; обычное редактирование сохраняет его, в том числе у архивированной группы. Сравниваются только реквизиты действующего формата, без вывода состава группы или исторических полномочий.

Противоречивые снимки дают ошибки. Отсутствие исходных реквизитов в событии создания, начало со снимка встроенной группы, необъяснённые ревизии и неполные участки истории остаются отдельными замечаниями для проверки. Более раннее время следующего сохранённого события не вызывает сортировку: порядок сохраняется, расхождение отмечается отдельно. Пропущенные события, значения, счётчики и время не восстанавливаются из текущей карточки. Статус соответствия полному источнику не означает полноту истории.

Проверка отменяемая, с общими ограничениями текста и числа замечаний; превышение завершает операцию ошибкой без частичного успешного результата. Результаты входят в существующие замечания исходного архива и зависимостей выбранных документов. Записи в хранилища не выполняются.

## Зависимости архивированных дисциплин

Общий инспектор сверяет сохранённое состояние дисциплины с действующими зависимостями её архивирования: назначениями преподавателей на группы, всеми парами черновиков, ещё не завершившимися опубликованными парами и аттестациями с открытой попыткой или исправлением. Блокировка входа не снимает назначение; несколько назначений одного преподавателя на одну дисциплину считаются одним преподавателем, как в рабочем сервисе. Пустой список групп назначения не блокирует архивирование. Завершение пары определяется по московскому времени: в момент окончания она уже относится к прошедшим. Старые версии публикаций и журнал сами по себе не становятся текущими зависимостями.

Для исходного архива используются только прочитанные документы этого архива; аттестации декодируются один раз существующим инспектором ведомостей. Повторный, неподдерживаемый или повреждённый источник ведомостей не используется для подтверждения зависимостей, даже если один документ удалось прочитать. Сводка состояний добавляется к проверке дисциплин; противоречия и недоступные источники входят в общий список замечаний.

Выбранный набор справочников проверяется по согласованным полным источникам дисциплин, учёток и расписания. Для зависимостей ведомостей внутри той же операции собирается кандидат аттестаций существующим механизмом проверки выбранных карточек, истории и исправлений. Кандидат проходит строгий декодер до передачи инспектору; неразрешённый конфликт, недопустимый выбор или несогласованная история оставляют зависимость неподтверждённой. Данные из другого запуска проверки или живых хранилищ не подставляются. Отсутствующий источник отличается от подтверждённого пустого документа; при отсутствии архивированных дисциплин проверка этих зависимостей не требуется.

Сборка кандидата общая для отдельной проверки аттестаций и проверки справочников. Последняя возвращает в UI только краткий результат структуры ведомостей; сам кандидат не выходит из внутренней операции. Обе проверки используют общий компонент сводки. Если аттестаций нет в обоих источниках, пустой согласованный документ не создаётся. Итоговые счётчики показываются только после завершённого обхода всех коллекций. В том же общем запуске кандидат проходит проверку ссылок, снимков периодов и времени сохранённых действий по выбранным источникам. Структура кандидата, его зависимости и право на применение различаются; исторические права не подтверждаются ни одним из этих статусов.

Открытые допсроки учитываются как открытые ведомости; опубликованные и отменённые попытки без открытых исправлений сами по себе не мешают архиву. Оценки, даты, состояния и назначения не меняются. Диагностика отражает сохранённые текущие состояния по действующим правилам, а не полномочия автора или допустимость архивирования в прошлом. Отмена и общие ограничения числа/текста замечаний сохраняются; превышение не возвращает частичный успешный результат.

## Зависимости выбранных ведомостей

Исходный архив и согласованный кандидат ведомостей в общей проверке используют один инспектор зависимостей. Он принимает уже декодированные данные и выбранные полные источники; повторного чтения хранилищ, декодирования и выбора приоритетного справочника нет. Проверяются группа, дисциплина, состав студентов, руководитель, преподаватель, председатель/члены комиссии, авторы создания/публикации, предыдущий руководитель и назначения из истории, авторы исправлений и их событий. Недоступный или несогласованный источник даёт неподтверждённую связь; отсутствующий ID в известном полном источнике — ошибку. Имена, текущие роли и блокировки не заменяют исторических сведений.

Снимок учебного года/семестра сверяется с уже выбранной полной историей периодов, её точной глобальной ревизией и моментом создания основной попытки. Совпадающий текст периода не заменяет эту связь; отсутствие снимка не восполняется из сегодняшнего календаря. Совпадение снимка по-прежнему не доказывает учебную программу группы или исторические полномочия. Старые назначения из снимков отдельно остаются неподтверждёнными.

Время сохранённых действий проверяется относительно завершения исходного архива либо момента общей проверки выбранных данных. Дата будущей сдачи сама по себе не является ошибкой. Адрес замечания содержит вид записи: ведомость, попытка, событие, исправление или событие исправления. Одинаковые ID разных коллекций не скрывают замечания друг друга. Инспектор поддерживает отмену и общие ограничения числа/текста замечаний; превышение прерывает операцию без частичного успешного итога. Оценки, даты, составы и хранилища не изменяются.

## Снимки дисциплин в учебных планах

Для исходного архива и выбранного набора используется общий индекс явных ревизий дисциплин. Он строится один раз по уже декодированному полному каталогу, только из снимков `after` после сохранённой границы старой истории. Снимок строки плана проверяется по ID, явной ревизии, названию, сокращению и моменту появления этой ревизии. Переименование текущей карточки не делает старую сохранённую версию неверной. Момент источника сравнивается как время, а не как строка; совпадающие моменты с разными часовыми поясами эквивалентны.

Отсутствующий ID в полном каталоге, отсутствующая явная ревизия современного формата, несовпадение названия/сокращения и ревизия, появившаяся позже события плана, дают отдельные ошибки. Старый формат каталога, ревизия 0 и отсутствие полного согласованного источника оставляют снимок неподтверждённым. Значения из текущей карточки и `before` первого изменения не используются для восстановления ранней истории. Подтверждается существование именно указанной версии, а не её актуальность во все последующие моменты, состав группы или исторические права автора.

Замечание содержит адрес события плана и конкретной строки, поэтому разные строки одной дисциплины не скрывают друг друга. Индекс и вложенные обходы истории, строк и периодов поддерживают отмену. Количество и текст замечаний ограничены общими бюджетами; превышение завершает операцию ошибкой без частичного успешного результата. Снимки программ/форм сравниваются с уже прочитанными объектами истории без повторной сериализации. Групповые снимки и неполная ранняя история остаются отдельными открытыми границами; учебные данные и хранилища не меняются.

## Выбранные планировщики, уведомления и журналы

Общая проверка выбранных данных получает списки планировщиков, уведомлений, историй журналов и снимки журналов из общего реестра семейств. Используется существующий механизм соответствия полному сохранённому источнику: записи только из одного источника сохраняются, каждый различающийся поддерживаемый ID требует выбора после просмотра. Ни один частичный или смешанный список не создаётся. Ключи планировщиков рассматриваются точно, включая каноническое кодирование владельца; ключи с похожими префиксами не объединяются. Повреждённый, повторный или неподдерживаемый источник не заменяется другой версией.

Для массивов и объектных форм уведомлений сохраняется форма корня и все служебные поля вне `items`. Конфликт версии/метаданных блокируется независимо от выбора строк. Порядок берётся из полного соответствующего источника. Для историй журналов дополнительно сохраняется относительный порядок общих ID: новое событие в начале списка допустимо, перестановка общих событий — нет. Правило абсолютных позиций ранее поддерживаемых базовых историй не меняется.

Строки снимков журнала сравниваются по ID студента только внутри точного ключа с одинаковой подтверждённой парой ID дисциплины/группы в обоих источниках. Неизвестная или неоднозначная область не получает автоматического соответствия. Просмотр конфликта показывает изменившиеся имя, карту отметок и карту оценок; значения возвращаются только авторизованному вызывающему коду, привязанному к проверенному файлу и снимку данных. Непоказанные дополнительные поля или слишком большой полный просмотр не разрешают выбор. ID студента в другом ключе остаётся другой записью.

После просмотра поддерживается выбор конфликтующей строки, но итоговый журнал должен целиком совпасть с одним полным источником, сохраняя односторонние записи, порядок этого источника, формат массива/документа версии 2 и дополнительные поля корня. Смешанный снимок не создаётся; различие формата и служебных полей не обходится выбором строк. Заблокированный снимок передаётся проверке истории как недоступный, без подстановки второй версии или пустого журнала. Для принятых снимков выполняется прежняя сверка последних применимых событий с ячейками. Совпадение текущего имени с ФИО учётки не используется вместо исторических данных.

В инспекции есть отдельное сравнение строк журналов, а технический отчёт содержит только счётчики, ID, имена изменённых полей и причины несравнимости. Значения отметок/оценок и ФИО не включаются в это сравнение отчёта. Перед скачиванием проверяется полнота результата нового сравнения; неполный результат не экспортируется как полный. Дополнение не мигрирует ключи и не изменяет оценки.

Зависимости списков проверяются существующими инспекторами по выбранным полным учёткам, каталогам и расписанию. Проверяются владелец планировщика, получатель уведомления, учебная область журнала, ID студентов/авторов/занятий, сохранённые утверждения контекста автора, значения событий, цепочки ячеек и последние изменения относительно выбранного снимка. Исторический состав, реальные полномочия и неполная ранняя история остаются неподтверждёнными. Для целей заданий/ответов отсутствующий выбранный источник не подменяется живым списком. Читаемая ссылка расписания с параметрами поиска отдельно отмечается как неподтверждённая цель: она не содержит постоянного ID занятия.

Время создания задач/уведомлений и сохранения событий журналов сравнивается с завершением исходного архива либо моментом проверки выбранного набора. Будущие даты начала/окончания задач и назначенных занятий сами по себе допустимы. Неизвестная заданная граница времени не заменяется часами устройства. Общий сборщик замечаний ограничивает количество и текст; вложенные обходы поддерживают отмену. Превышение бюджета и отмена не возвращают частичный успешный результат. Сам выбор ограничен совокупными бюджетами ключей, текста, записей и результата, а не отдельным лимитом на каждый частный список.

В UI показаны только результаты источников и замечания, с поиском, фильтром состояния и страницами по 20 источников. Полные выбранные списки и их значения остаются внутри проверки. Права, исходный файл, снимок localStorage и ревизия выбора повторно проверяются после асинхронной операции. Запись, миграция, восстановление и изменение владельцев не выполняются.

## Выбранные задания, ответы и попытки

Общий реестр полных списков включает задания и ответы. Используются те же строгие декодеры и защищённые адреса, что при сравнении и просмотре конфликтов. Родительская карточка сравнивается целиком, включая счётчик и массив попыток; отдельный адрес попытки содержит ID ответа и ID попытки. Все различающиеся карточки и попытки требуют согласованного выбора после просмотра. Выбор должен совпасть с одним полным сохранённым списком, сохранив записи только из другого источника. Несовместимые выборы карточки и её попыток, перестановка попыток и смешанный список не создают кандидат. Счётчики и ID не пересчитываются.

Ответ без непустой сохранённой истории попыток не подтверждает полный источник ответов: он остаётся заблокированным с явной причиной. Старый ответ по-прежнему можно сравнить как карточку, но история не достраивается из её полей. Противоречие карточки, счётчика и последней попытки отклоняется существующим декодером сравнения. Относительный порядок общих ID попыток сохраняется отдельно внутри каждого ответа; перестановка карточек не считается изменением порядка разных историй. Пустой подтверждённый список отличается от отсутствующего или заблокированного.

Согласованные полные списки передаются проверкам связей и целям уведомлений внутри того же запуска. Проверяются точные ID задания, ответа, студента, дисциплины и группы; несколько карточек одного студента по заданию требуют отдельного разбора. Наличие учётки не подтверждает исторический состав группы или права. Недоступный выбранный список не заменяется исходным архивом, живыми данными или записью с похожим именем.

Общий инспектор исходного архива и выбранного набора проверяет согласованность карточек с попытками и даты создания/изменения/отправки/проверки относительно соответствующей границы времени. Дата изменения задания раньше создания — противоречие. Будущие дата занятия и дедлайн допустимы. Для выбранных вложений без согласованного файлового источника остаётся отдельное замечание; проверка исходных архивных файлов сохраняется. Все обходы поддерживают отмену и совокупные пределы записей/текста, без частичного успешного результата. UI получает только сводки источников и замечания, а не тексты ответов или оценки. Применение данных не выполняется.

## Ограничения файловой диагностики

Инспекторы учебных вложений, файлов переписки и материалов используют общий сборщик: до 25 000 уникальных замечаний и 16 МиБ текста. Общая инспекция документов применяет тот же предел к сумме замечаний всех разделов, сохраняя прежние правила дедупликации. Превышение прекращает проверку целиком, а не обрезает список и не возвращает частичный успешный результат.

Файловые обходы и сверка дополнительных индексов ограничены 500 000 шагами на инспектор с проверкой отмены и уступкой управления каждые 128 шагов. Для текущих ключей уникальных индексов действует совокупный предел 16 МиБ, включая повторную обработку разных индексов. Сравнение содержимого однозначных копий вложений ограничено 64 МиБ суммарного объёма проверяемых пар; повторно найденная в кэше пара этот объём не расходует. Бинарные файлы не открываются и не декодируются. Правила поддержки схем, индексов, областей и владельцев не менялись; проверка текущих коллизий по-прежнему не подтверждает будущие записи или восстановление.

## Выбранные настройки интерфейса

Общий запуск учитывает сохранённые тему, вид планировщика и виды расписания по точным ключам. Используются существующие наборы допустимых значений и защищённый просмотр скалярных конфликтов. Различающиеся значения принимаются только после просмотра и явного выбора версии; одинаковые значения и настройки только из одного источника сохраняются без назначения приоритета. Отсутствующие настройки не получают значения по умолчанию. Повторный ключ, неизвестное значение, неподдерживаемый ключ семейства и лишний/неоднозначный выбор блокируются; другая версия не подставляется вместо повреждённой.

Вид расписания остаётся привязан к буквальному ID в исходном ключе: проценты и двоеточия внутри ID не декодируются и не переименовываются. Наличие владельца проверяется существующим инспектором по выбранному полному справочнику учёток внутри той же операции. Отсутствующий/несогласованный справочник оставляет ссылку неподтверждённой, известный пустой справочник позволяет зафиксировать отсутствующий ID. Текущая роль не используется как доказательство исторических полномочий. Защищённый просмотр различающихся значений дополнительно сохраняет прежнюю проверку ID владельца в обоих исходных справочниках.

Ключи выбора демонстрационной учётки/роли и неизвестные варианты семейств показаны как неподтверждённые источники, без выбора их значений. Они не исчезают из общего результата и не получают успешный статус за счёт проверки визуальных настроек. Восстановление входа остаётся отдельным решением. В UI возвращаются только состояние, источник, ключ, счётчики и замечания; выбранные значения остаются внутри проверки. Настройки отображаются отдельным списком с поиском, фильтром и страницами по 20. Подпись общего запуска изменена на «Проверка выбранных данных» в соответствии с его объёмом.

Проверка ограничена 25 000 входных записей настроек, совокупным бюджетом текста и результата; счётчики не показываются как полные после ранней блокировки. Обходы поддерживают отмену. Сервис проверяет просмотренный адрес, доступ, файл, снимок localStorage и ревизию выбора до и после операции. Общий инспектор настроек использует ограниченный сборщик замечаний и для исходного архива. Никакие настройки, выбранная учётка и роль не применяются и не записываются.

## Даты и пределы диагностики переписки

Инспекция исходного архива передаёт переписке его собственное время завершения. Во всех читаемых поколениях ящиков сохранённый `sentAt` сообщения и числовой `createdAt` беседы проверяются относительно этой границы. Дата позже завершения архива — противоречие; ровно на границе допустима. Моменты сравниваются по времени, поэтому эквивалентные записи с разными часовыми поясами не расходятся только из-за формата. Числовая дата беседы за пределами диапазона Date отмечается отдельно. Если граница не задана или не читается, имеющиеся даты остаются неподтверждёнными; часы устройства не подставляются.

Диалог с сообщениями без `sentAt` получает одно замечание о неподтверждённой дате. Отображаемое время и числовой ID не превращаются в дату или доказательство порядка. Пустая переписка не требует вымышленной даты; отсутствующие и повреждённые ящики не дополняются другими поколениями. Ранее действующие проверки циклов, порядка дат ответа/оригинала, копий доставки, файлов и состава сохраняются; по расхождению часов даты не исправляются и сообщения не перенумеровываются.

Основной инспектор, сверка копий доставки и цепочки ответов используют ограниченный сборщик замечаний: 25 000 уникальных замечаний и 16 МиБ текста на инспектор с повторной проверкой общего результата документов. Вложенные обходы ограничены 500 000 контрольными шагами с отменой и уступкой управления каждые 128 шагов. Суммарно читается не более 25 000 сохранённых копий сообщений во всех поколениях; списки диалогов, бесед и участников также ограничены до обхода, а участники проверяются с отменой. Входной текст семейств переписки ограничен общим бюджетом. Превышение не выдаёт частичный успешный результат и не отрезает старые копии. Значения сообщений, дат и имена участников в новые замечания не добавляются.

Принадлежность, исторический доступ, совместимость старых поколений, перенос счётчиков и недостающих дат, восстановление и отправка сообщений этим этапом не подтверждаются. Реальные ящики и файлы не меняются.

## Полнота сводки документов

Начальная инспекция, панель допуска и скачивание отчёта используют одну проверку полноты сводки документов. Для каждого вида из текущего реестра должен быть ровно один результат с его точным ключом; отсутствующий в архиве документ подтверждается явной строкой «нет в архиве», а не отсутствием строки. Пустая сводка с нулевыми счётчиками, пропуск/повтор раздела, неизвестный вид или неподдерживаемые поля не считаются полной проверкой. Старый частичный результат требует новой инспекции.

Проверяются обязательные собственные поля, типы и допустимые состояния, неотрицательные целые безопасные счётчики/ревизии, сообщения и адреса замечаний, уникальность замечаний и непроверенных ключей, а также точное соответствие итогов деталям. У отсутствующего документа не может быть ревизии или положительного числа записей/ключей/документов. Пустой явный источник отличается от отсутствующего. Неизвестные поля сводки не отбрасываются и не выгружаются как поддерживаемый протокол.

При частичной сводке сохраняются поддерживаемые известные ошибки и причины блокировки вместе с отметкой о неполноте. Если входная форма или пределы не позволяют безопасно разобрать сводку, панель выдаёт только блокировку неполного результата. Непроверенный непортальный ключ не попадает в блокировки. Нечитаемый документ остаётся причиной блокировки даже при пропущенном отдельном замечании. Поиск таких замечаний использует предварительный индекс, без повторного обхода всех замечаний для каждого документа.

Массивы и текст ограничены действующими пределами: до 25 000 элементов списка, отдельные совокупные бюджеты текста сводок/замечаний/ключей по 16 МиБ. Превышение и несовместимая структура не превращаются в частичный успешный результат. Экспорт отказывается создавать файл; начальная инспекция не связывает неполный результат с просмотром конфликтов. Счётчики и пропущенные разделы не исправляются. Даже полная сводка без блокировок требует итоговых проверок владельцев, полномочий, выбранных версий и актуальности всех источников; разрешение записи этим не выдаётся.

## Покрытие прикладных файловых схем

Проверка внешнего формата архива сохраняет произвольные прикладные поля и дополнительные хранилища IndexedDB. Поэтому начальная инспекция отдельно проверяет покрытие схем трёх файловых баз: материалов, вложений переписки и учебных файлов. Каждое дополнительное хранилище, включая пустое, получает замечание о неподтверждённой схеме. Оно не считается совместимым только потому, что его значения удалось прочитать как типизированные данные архива.

В записях материалов и вложений переписки проверяются все собственные сохранённые поля. Поля вне поддерживаемого списка дают отдельное замечание для каждой записи; их имена и значения не выводятся. Тот же список полей используется сравнением файловых версий. Известные метаданные и связи продолжают проверяться; неизвестные поля не удаляются и не исправляются. Учебные файлы сохраняются непосредственно как Blob/File: их типизированные поля проверяет внешний декодер, а допустимость файловой записи и ссылки — действующая диагностика учебных вложений.

Замечания включаются в общую сводку, панель допуска и технический отчёт. По правилу целого архива неподтверждённая схема блокирует восстановление; совместимость не выводится из отсутствия текущих ссылок. Сводки показывают число дополнительных хранилищ и записей с неподдерживаемыми полями, не подтверждая владельцев, права, версии базы или возможность будущей записи. Превышение 25 000 записей, 500 000 операций или бюджета текста 16 МиБ прерывает проверку; есть отмена и уступка интерфейсу каждые 128 шагов. Бинарные значения не декодируются, исходные хранилища не открываются и не меняются.

## Актуальность текущих файлов при инспекции

Начальная инспекция фиксирует полный сериализованный снимок каждой из трёх текущих файловых баз и повторно читает их перед выдачей результата. Сверяются присутствие и версия базы, все хранилища, первичные ключи, значения, метаданные File/Blob, содержимое, пути ключей, генераторы и определения индексов. Изменение содержимого без повышения версии базы, добавление/удаление записи и изменение дополнительного хранилища не обходят эту сверку. Записи только из браузера также полностью читаются и учитываются в пределах; неизвестное сериализуемое поле участвует в отпечатке независимо от подтверждения его прикладной схемы.

Компактные внутренние отпечатки строятся через SHA-256 над блоками точных кодовых единиц UTF-16, затем над их длиной и упорядоченными отпечатками. Для схем и записей используются отдельные структурные уровни. Содержимое, значения файловых метаданных и сами служебные отпечатки не передаются интерфейсу или техническому отчёту. Метки времени чтения и порядок перечисления хранилищ/индексов/записей не являются изменением данных. Порядок составного ключа и содержимое значений сохраняют значение. Этот служебный отпечаток не заменяет SHA-256 исходного файла архива, подпись или подтверждение подлинности данных.

Два прохода имеют отдельные общие бюджеты для трёх баз: 25 000 записей, 500 000 узлов, 16 МиБ текста и 64 МиБ вложений. Повторный проход не удерживает полный список сериализованных файлов. Исходный текст хешируется порциями по 32 768 кодовых единиц с бинарным буфером до 64 КиБ; служебный перечень содержит только длину и отпечатки порций. Большие канонические строки и само чтение Blob/File остаются ограниченными полным бюджетом, а не объявляются потоковой обработкой. Есть отмена и уступка интерфейсу. Ошибка чтения/кодирования/отпечатка или превышение предела не дают частичного результата и не связывают просмотр конфликтов с новой инспекцией.

Перед выдачей результата также сверяются учётка, localStorage, наличие/версии баз и поколение проверки. При изменении файлов предлагается проверить архив заново. Чтение выполняется отдельными readonly-транзакциями каждой базы; повторная сверка не создаёт общего атомарного снимка и не предотвращает последующее изменение уже проверенной базы. Эта граница указана в предупреждении результата. Перед будущим применением всё равно нужны повторные проверки, подтверждение полномочий, атомарность и откат; восстановление этим этапом не выполняется.

## Защищённый просмотр файловых метаданных

Для различий поддерживаемых файловых записей с полным разбором доступно отдельное действие «Сравнить метаданные». По явному запросу действующего настройщика окно показывает все сохранённые поддерживаемые метаданные обеих версий: имя/тип/размер, даты, область, категорию, сохранённое имя загрузившего, описание и закрепление, а также метаданные File при наличии. Совпадающие поля тоже видны. Отсутствие поля, сохранённое undefined и пустая строка различаются; даты показываются по Москве вместе с исходным числом миллисекунд. Значения выводятся как текст без выполнения разметки.

Просмотр привязан к отпечатку исходного файла архива, учётке/ревизии, снимку localStorage, точному адресу записи и внутреннему отпечатку всей соответствующей файловой базы начальной инспекции. База повторно читается до подготовки результата и после неё; оба отпечатка должны совпадать с привязкой. Сведения из другого хранилища, файл с совпадающим именем и текущие справочники вместо источника не подставляются. Ранний результат без файловой привязки требует новой инспекции. Неизвестные поля, неподдерживаемая схема и неполный разбор не открываются как частично подтверждённая версия.

Повторные файловые чтения сохраняют действующие пределы и отмену. Текст таблицы ограничен 128 КиБ с ранним отказом для большого отдельного поля; усечённый текст не показывается. Пользователь видит время сверки. После известных событий изменения данных, возврата фокуса или видимости файловые метаданные скрываются до повторного просмотра; фактическое расхождение требует новой инспекции. Обычные черновики выбора сбрасываются по прежней проверке их источников, а не только из-за возврата фокуса файлового окна. Чтения не образуют общего атомарного снимка и не гарантируют обнаружение последующих изменений без события.

Бинарное содержимое не открывается и не загружается пользователю. Показывается только факт совпадения/различия байтов; это не полный просмотр файла. Режим не отмечает файловую запись просмотренной для выбора: кнопок выбора нет, а прямой вызов сервиса отклоняется. Метаданные и время просмотра не добавляются в технический отчёт; внутренние отпечатки остаются в памяти сессии и освобождаются вместе с привязкой. Принадлежность, права, выбор и применение файловой версии остаются открытыми G03.

## Исторические календари публикаций расписания

Начальная инспекция и общий запуск выбранных данных используют одну сверку явных событий публикации с историей календарей групп. Для каждой копии занятия берётся последнее состояние календаря строго до события публикации. Более поздние закрытие, переоткрытие, перенос каникул или добавление неучебного дня не подставляются в прошлое. Снимок семестра этого календаря должен подтверждаться историей выбранных общих периодов на момент сохранения календаря. Неподтверждённый снимок не используется как основание разрешения или запрета.

Из действующей функции правил публикации повторно используются три ограничения: закрытый период, каникулы и явно заданный неучебный день. Их известное нарушение даёт ошибку с техническими ID публикации, занятия и календаря; названия групп, семестров и неучебных дней в новое замечание не попадают. Состояния и даты не исправляются, занятия не переносятся. Если полная читаемая история показывает отсутствие настроенного календаря на дату, это отдельный счётчик без нового запрета или подтверждения учебной фазы. Пустая публикация не требует вымышленного календаря для отсутствующих дат.

События изменения календаря с тем же временем, что и публикация в другом документе, не получают искусственный общий порядок. Если изменение затрагивает дату занятия, соответствующий календарь остаётся неподтверждённым. При этом однозначный запрет другого календаря сохраняется как известная ошибка. Старый `saved-snapshot` и недатированная явным событием неделя формата 1 не проверяются по времени фиксации снимка или текущим реквизитам недели. Отсутствующий/нечитаемый/невыбранный источник календарей получает замечание; данные исходного архива и браузера не подставляются вместо выбранного документа.

Обход идёт по хронологии публикаций с индексом одновременных событий и актуальными состояниями календарей групп. Результаты по дате кэшируются до изменения календаря этой группы. Для каждого списка событий/версий действует предел 25 000; совокупно проверяется до 25 000 копий занятий, до 500 000 операций и 16 МиБ текста индексов/кэша. Замечания имеют общий предел 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; неподдерживаемый порядок дат и превышение пределов не дают частичного результата.

Сводка начальной инспекции отдельно считает сопоставления, известные запреты, отсутствие настройки и неподтверждённые копии. При выбранных данных используются только выбранные полные источники расписания, календарей и периодов. Наличие исторических ID и дат не подтверждает полномочия авторов. Черновики, операции журнала/ведомостей, ранние публикации без точного события, общий атомарный снимок и восстановление остаются отдельными границами G03.

## Исторические календари операций ведомостей

Начальная инспекция и общий запуск выбранных данных используют одну сверку событий ведомостей и исправлений с состояниями календарей строго до операции. Повторно используется предикат действующей проверки закрытого периода: совпадение ID семестра либо попадание затронутой даты в диапазон закрытого календаря той же группы. Запреты публикации расписания по каникулам и праздникам на ведомости не переносятся. Позднее закрытие или переоткрытие не заменяет прежнее состояние.

Назначения восстанавливаются только из явной истории. Перенос проверяет прежнюю и новую даты; изменение реквизитов зачётки и руководителя — даты всех уже существовавших попыток, включая опубликованные и отменённые, как действующее хранилище. Исправления используют неизменяемое назначение опубликованной ведомости; текущая карточка не подставляется. `legacy-snapshot` не подтверждает первоначальную дату: до явного назначения она остаётся неизвестной. При этом известный запрет по подтверждённому ID семестра сохраняется независимо от отсутствующей даты.

Снимки семестров проверяются по выбранной истории общих периодов. Неподтверждённый семестр ведомости не используется для запрета по совпадению ID; однозначная известная дата всё ещё может показать запрет по подтверждённому календарю. Неподтверждённые снимки календарей, отсутствующий полный источник и одинаковое время затрагивающего изменения календаря и операции дают замечания без вымышленного порядка. Однозначная ошибка другого календаря не скрывается. Отсутствие затрагивающей настройки при полной читаемой истории не вводит обязательный календарь.

Оба потока истории сохраняют собственный порядок. Исправление возможно лишь после публикации, когда дата уже неизменяема; расположение обычного события перед исправлением с тем же временем не используется для разрешения междокументного порядка. Сводка считает события, сверенные события, известные запреты, отсутствие настройки и неподтверждённость. Запрет и неподтверждённость могут пересекаться. В выбранном наборе используются только выбранные полные ведомости, календари и периоды, без подстановки архива или браузера.

Пределы: 25 000 записей на каждый входной список, совокупно 25 000 событий двух потоков и 25 000 попыток, 500 000 учитываемых операций, 16 МиБ текста индексов; замечания ограничены общим сборщиком 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу. Превышение пределов или невозможная связь события отклоняют проверку целиком. Новые сообщения содержат технические ID без имён, оценок и причин исправлений. Исторические полномочия, программа группы, действия журнала, восстановление и откат этим не подтверждены.

## Исторические календари изменений журналов

Начальная инспекция и общий запуск выбранных данных сверяют читаемые события отметок и оценок с прежним состоянием закрытия периода. Учебная область должна однозначно разрешаться по точным ID выбранных дисциплин и групп, а занятие — иметь стабильный `managed:` ID. Дата получается из последней строго более ранней версии публикации той же пары дисциплины и группы. Последующий перенос обновляет дату только для более поздних событий; отмена и перенос в другую область сохраняют прежнюю дату оставшейся журнальной записи по действующему правилу хранилища. Итоговая карточка журнала, черновики, встроенные занятия и дата, извлечённая из старого ключа, не используются.

`saved-snapshot` подтверждает снимок опубликованной недели только после времени его фиксации; это время не считается первоначальной публикацией и не используется для ранних операций. Затрагивающая занятие публикация или фиксация снимка с тем же временем, что и изменение журнала, получает замечание без выбора общей последовательности. Расписание формата 1 и отсутствие более раннего снимка не подменяются текущими данными.

Календарь берётся строго до изменения журнала, снимок его семестра проверяется по согласованной истории общих периодов. Известное попадание даты в закрытый период даёт ошибку по общему действующему предикату редактирования. Праздники и каникулы не становятся запретом журнала. Равное время затрагивающего изменения календаря, неподтверждённый снимок периода или отсутствующий полный источник дают замечания. Ошибка другого однозначного календаря сохраняется. Отсутствие затрагивающей настройки в полной истории не вводит обязательность календаря.

События состава и пакетного демозаполнения не хранят полный перечень изменённых занятий и остаются неподтверждёнными; он не достраивается по итоговым ячейкам или тексту события. В выбранном запуске используются только выбранные полные расписание, календари, периоды и списки журнала. Повреждённые списки сохраняют свои ошибки и не включаются в число прочитанных событий. Сводка отдельно считает сопоставления, известные запреты, отсутствие настройки и неподтверждённость; запрет и неподтверждённость могут пересекаться. Новые сообщения содержат только технические ID событий, ключей и календарей, без имён, отметок, оценок и контекста автора.

Один обход обрабатывает все читаемые истории; события сортируются по абсолютному времени, а состояния публикаций и календарей продвигаются хронологически. Повторяющийся ID занятия внутри одной версии или общего набора saved-snapshot отклоняет сверку целиком: дата не выбирается по последнему совпадению. Пределы: 25 000 списков и совокупно событий, 25 000 копий занятий, по 25 000 записей входных историй календарей/периодов и версий публикации, 500 000 учитываемых операций, 16 МиБ текста индексов. Замечания используют общий предел 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; превышение пределов отклоняет сверку целиком. Это проверка сохранённых утверждений, а не полноты аудита, исторического состава, полномочий или разрешения восстановления.

## Исторические запреты изменения учебных периодов

Начальная инспекция и общий запуск выбранного набора сверяют явные события изменения годов и семестров с календарями строго до события. Общий предикат используется и обычным сохранением справочника: закрытый календарь любой группы запрещает изменение связанного года либо семестра по точному ID. Названия, диапазоны дат, текущая группа пользователя и сегодняшнее состояние календаря не заменяют эту связь. Создание года или семестра не получает нового запрета.

Снимок года и семестра календаря должен подтверждаться историей проверяемых общих периодов на момент сохранения календаря. При неподтверждённом снимке разрешение или запрет по нему не выдаются. Изменение связанного календаря с тем же временем, что и событие справочника, получает замечание без вымышленного междокументного порядка; известная ошибка другого однозначного календаря сохраняется. Поздние закрытие и переоткрытие не подменяют прошлое. Отсутствие полного источника остаётся неподтверждённым; полная история без связанного календаря не делает настройку обязательной. Выбранный запуск использует только выбранные полные периоды и календари без возврата к архиву или живым данным.

Состояния календарей индексируются по ID года и семестра, поэтому несвязанные группы не перебираются для каждого изменения. Каждый входной список ограничен 25 000 событиями; учитывается до 500 000 операций и 16 МиБ текста индексов. Замечания ограничены общим сборщиком 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; нарушение порядка дат и превышение пределов не возвращают частичный результат. Если событий изменения нет, календарные индексы не строятся. Сводка отдельно считает изменения, сопоставления, известные запреты, отсутствие настройки и неподтверждённость; запрет и неподтверждённость могут пересекаться при нескольких календарях. Новые сообщения содержат технические ID без названий и значений изменённых реквизитов. Исторические полномочия и восстановление не подтверждены.

У заданий и ответов текущая дата занятия и время изменения не заменяют отсутствующий снимок назначения на каждое историческое действие. Проверка их прошлого закрытия и оставшиеся неподтверждённые учебные операции требуют отдельных источников; текущие карточки не подставляются в историю.

## Исторические календари назначений учебных планов

Начальная инспекция и общий запуск выбранного набора используют одну сверку явных событий назначения плана группе с состоянием календарей строго до операции. Общая функция используется также обычным сохранением: закрытый календарь прежнего семестра той же группы запрещает смену ID плана либо удаление или перенос прежней пары «номер семестра → ID периода». Новая версия того же семейства плана имеет другой ID и считается сменой плана. Первое назначение, добавление новых семестров и обновление снимков при сохранении тех же ID плана и пар не получают нового запрета. Правки карточек планов не подменяются событиями назначения.

Исходное назначение берётся из точного `before` цепочки истории. Для каждого его семестра сохраняется результат сверки снимка с историей общих периодов на момент прежнего события `after`, а не на момент поздней правки. Снимок календаря отдельно проверяется на момент его сохранения. Неподтверждённый прежний снимок или снимок календаря не становится основанием известного запрета. Текущие карточки групп, планов и календарей не подставляются в прошлое. Имена, даты и номер семейства не заменяют точные ID.

Событие календаря с тем же временем и той же защищаемой областью требует отдельного разбора без вымышленного порядка по ID или позиции списка. Однозначный запрет другого календаря сохраняется. Поздние закрытие и переоткрытие не меняют исторический результат. Отсутствие полного календарного источника остаётся неподтверждённым; полная история без связанного календаря не делает настройку обязательной. В выбранном запуске используются только выбранные полные планы, календари и общие периоды.

Предикат строит набор затронутых прежних периодов один раз по парам семестров. Исторические календари индексируются по группе и периоду; несвязанные группы и семестры не перебираются для каждого изменения. Каждый входной список ограничен 25 000 событиями, учитывается до 500 000 операций, текст индексов ограничен 16 МиБ. Замечания используют общий предел 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; невозможная цепочка, нарушенный порядок дат и превышение пределов не возвращают частичный результат. При отсутствии событий назначения календарные индексы не строятся.

Сводка отдельно считает назначения, изменения прежних соответствий, события без таких изменений, сопоставления, известные запреты, отсутствие настройки и неподтверждённость. Запрет и неподтверждённость могут пересекаться при нескольких календарях; счётчики не объявлены взаимоисключающими долями. Новые замечания содержат технические ID событий, периодов и календарей без названий, ФИО и содержимого плана. Сверка не подтверждает исторические полномочия, полноту учебной программы группы или разрешение восстановления.

Новый инспектор загружается отдельным модулем при обработке документа учебных планов в обоих запусках. Перед загрузкой и внутри инспектора проверяется отмена. Ошибка загрузки прерывает сверку и не подменяется частичным успешным результатом. Текущие данные не перечитываются как запасной источник после загрузки модуля.

## Исторические календари назначений преподавателей

Начальная инспекция и общий запуск выбранных данных сверяют явные события назначений по типам занятий с более ранними календарями групп. Общий предикат применяется также обычным сохранением без изменения правил: переключение между общим и посеместровым режимом запрещается любым закрытым календарём той же группы. Это относится и к первому переходу из отсутствующего уточнения, которое действующая запись трактует как общий режим. При сохранении режима проверяется только календарь изменённого ID семестра назначения.

Изменением семестра считается добавление, удаление и любое различие всей сохранённой строки, включая типы занятий, их порядок, снимок года/семестра и ревизию справочника. Сравнение повторно использует `sameTeachingData`; смысл не сужается до совпадения дат или набора типов. Изменение другого семестра и календарь другой группы не получают нового запрета. Праздники и каникулы не вводят дополнительного запрета назначения.

При сохранении режима прежний снимок семестра проверяется на момент сохранения прежней версии назначения, новый — на момент новой версии. Карты подтверждения содержат все сохранённые строки: отсутствие ID в одной из полных версий означает добавление или удаление, а не подстановку источника. Неподтверждённый снимок назначения не используется для известного запрета изменения этого семестра. Для смены самого режима сравнение периодов назначения не требуется; источник календаря и его снимок периода проверяются отдельно. Текущее назначение и поздние ревизии не заменяют историю.

Календари берутся строго до события. Равное время изменения назначения и затрагивающего календаря даёт замечание без искусственного общего порядка; однозначный запрет другого календаря сохраняется. Поздние закрытие и переоткрытие не меняют прошлый результат. Отсутствие полного календарного источника остаётся неподтверждённым, полная история без связанного календаря не делает настройку обязательной. В выбранном наборе используются только выбранные полные назначения, календари и общие периоды.

Набор изменённых периодов строится один раз. Календарные состояния индексируются по группе и по паре «группа → период»: смена режима проверяет все календари группы, локальное изменение — только нужные семестры. Каждый входной список ограничен 25 000 событиями; учитывается до 500 000 операций и 16 МиБ текста индексов. Замечания используют общий предел 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; невозможная цепочка, нарушенный порядок дат и превышение пределов не возвращают частичный результат. При пустой истории календарные индексы не строятся.

Новый инспектор загружается отдельным модулем в обоих запусках; отмена проверяется до загрузки и внутри него. Ошибка загрузки прерывает сверку без запасного источника или частичного успеха. Сводка отдельно считает события, смены режима, изменения без затрагивания режима/семестров, сопоставления, известные запреты, отсутствие настройки и неподтверждённость; счётчики могут пересекаться. Новые замечания содержат только технические ID событий, семестров и календарей без ФИО, названий и содержимого назначения. Общие назначения учёток, исторические права, проверка будущих публикаций на момент изменения и восстановление остаются отдельными зависимостями.

## Защита будущих публикаций при изменении назначения преподавателя

Начальная инспекция и проверка выбранных полных источников сопоставляют каждую сохранённую версию назначения в режиме `periods` с более ранними версиями публикаций расписания. Используется общий с действующим `canTeachLesson` предикат покрытия даты и типа занятия. Общие назначения учётки и полномочия отделены от этого предиката: сегодняшняя роль или членство не становятся историческим доказательством. Существующее сохранение назначения сохраняет прежние проверки и поведение.

Публикации проигрываются хронологически целыми неделями. Новая версия заменяет прежнюю неделю, включая явную очистку: удалённые занятия не остаются действующими. Сопоставляются точные ID преподавателя, дисциплины и группы. Будущим считается занятие, чьё окончание с московским смещением `+03:00` строго позже события назначения; начавшееся, но ещё не завершённое занятие тоже защищено. При подтверждённых снимках семестров назначения исключение такой даты или типа даёт известную ошибку. Пустой список разрешённых периодов не требует вымышленных снимков семестра для определения запрета.

Публикация с тем же временем не получает порядка относительно назначения из другого документа. Для затронутой недели остаётся разбор; независимое известное нарушение другой недели сохраняется. Начальный `saved-snapshot` подтверждает состояние только после времени его захвата. Текущие публикации, прежние карточки журнала и более поздние версии не подставляются в прошлое. Отсутствующий источник расписания и отсутствующая/пустая история различаются. Даже при известных ошибках полнота раннего расписания, старые общие назначения и исторические полномочия остаются неподтверждёнными.

Состояние индексируется по учебной области и неделе; несвязанные области не перебираются для каждой правки. Каждый список ограничен 25 000 событиями, суммарные копии занятий — 25 000, учитывается до 500 000 операций и 16 МиБ текста индексов. Повтор ID внутри версии или общего начального снимка, нарушенный порядок, некорректное время, отмена и превышение пределов прерывают всю сверку без частичного результата. Замечания ограничены общим сборщиком 25 000 / 16 МиБ; в новых сообщениях сохраняются только технические ID события, версии публикации и занятия. Инспектор загружается отдельным модулем; ошибка загрузки не подменяется успешной проверкой.

## Хронология ссылок публикаций на назначения преподавателей

В том же отложенно загружаемом модуле начальная инспекция и проверка выбранных полных источников дополнительно сверяют время и выбор ревизий назначения для архивных копий занятий. Действующая публикация заново читает назначение по точной тройке «преподаватель → дисциплина → группа» и сохраняет его ID и ревизию даже в режиме `general`. Для обычной версии `published` историческая сверка проигрывает строго предшествующие события назначения и сопоставляет явную ссылку с последней такой ревизией. Ссылка на уже заменённую ревизию получает ошибку по этому действующему правилу. В обоих видах версии ссылка на ревизию, сохранённую позже публикации/захвата, является известной ошибкой времени.

События назначения с тем же временем не упорядочиваются относительно публикации по положению в разных списках. Связанная учебная область остаётся на разбор; ошибка ссылки на явно будущую ревизию от этого не скрывается. Одновременно изменённое назначение другой области не мешает однозначной сверке. У `saved-snapshot` время захвата не заменяет время исходной публикации, поэтому последняя ревизия на момент захвата не становится обязательной для старой ссылки. Отсутствующая ссылка при существовавшем явном назначении требует разбора старой схемы и не дополняется текущей ревизией. Совпадение или отсутствие явного назначения не подтверждает общие назначения учётки и исторические права.

Существующая базовая инспекция отдельно проверяет наличие указанной ревизии, точные учебные ID и покрытие даты/типа занятия. Хронологическая проверка не дублирует эти ошибки для неизвестной или чужой ссылки. Текущие карточки, оставшиеся записи журнала и финальный снимок назначения не используются для выбора прошлой ревизии. Публикация позже границы архива не подтверждает выбор ревизии. Отсутствующий источник расписания и отсутствующая/пустая история различаются; полнота ранних данных остаётся открытой.

История назначения проигрывается один раз вместе с хронологией публикаций; ревизии и равные времена индексируются по техническим ID учебной области. Каждый входной список ограничен 25 000 событиями, суммарные копии занятий — 25 000, операции — 500 000, текст индексов — 16 МиБ. Повтор ID внутри версии или общего начального снимка, нарушение порядка/уникальности ревизий, некорректная граница, отмена и превышение пределов прерывают всю сверку без частичного результата. Общий сборщик замечаний ограничен 25 000 / 16 МиБ, в новые сообщения не попадают имена, даты занятий и содержимое назначения. Сводка отдельно считает копии, совпадения, отсутствие прежнего явного назначения/ссылки, будущие или заменённые ревизии, структурно неподтверждённые ссылки, равные времена и начальные снимки; это разнородные счётчики, а не разбиение одного количества.

## Исторические аудитории и публикации

Оба запуска инспекции дополнительно сопоставляют аудитории с архивом публикаций. Для обычной версии `published` с явным `roomId` подтверждённая сохранённая карточка сравнивается с последней строго предшествующей ревизией этой аудитории: действующая публикация требует актуальную карточку, включая ревизию при неизменных названии и корпусе. Уже заменённая ревизия даёт ошибку. Прежние проверки существования, состояния, реквизитов и дат ссылки сохраняются отдельно. Правка той же аудитории с равным временем оставляет разбор; правка другой аудитории не мешает известной сверке. У `saved-snapshot` последняя ревизия на момент захвата не подставляется в исходную публикацию. Занятие только со старым названием требует разбора допустимости сохранения прежней пары без ID: история черновиков отсутствует.

Для перехода `active → archived` проигрываются строго предшествующие публикации целыми неделями. Замена и явная очистка недели убирают старые занятия из действующих. Занятие с окончанием строго позже времени архивирования в `+03:00` защищает аудиторию: начавшееся, но ещё не завершённое занятие тоже учитывается. Точный `roomId` даёт известный запрет; без ID действующий запрет учитывает кандидата по прежнему названию. Ключи включают название, метку «корпус · название» и псевдонимы всех прежних ревизий этой аудитории, как в действующем `indexRooms`. Набор нормализованных ключей выделен в общий чистый помощник без изменения правил. Псевдоним, появившийся позже архивирования, не действует задним числом. Совпадение со старым названием остаётся кандидатом, а не доказанной идентичностью; наличие одноимённой аудитории не отменяет существующий запрет для кандидатов.

Публикация с равным временем оставляет неопределённость для затронутой недели; известная ошибка другой недели сохраняется. Ранний снимок устанавливает действующее состояние только после захвата. Текущие черновики, финальное расписание, оставшиеся карточки журнала и поздние названия не подставляются в прошлое. История черновиков, полнота раннего расписания, исторические полномочия и разрешение восстановления остаются открытыми даже при известных запретах.

Новый инспектор загружается отдельно из общей проверки аудиторий, поэтому работает и для начального архива, и для выбранных полных источников. Состояние публикаций индексируется по точному ID/старому ключу аудитории и неделе; каталог проигрывается по ID. Входные списки ограничены 25 000 событиями, суммарные копии занятий — 25 000, учитываемые операции — 500 000, текст индексов — 16 МиБ. Замечания ограничены общим сборщиком 25 000 / 16 МиБ. Дубли ID внутри версии/общего начального снимка, нарушенный порядок/уникальность ревизий, некорректное время, отмена, превышение пределов и ошибка загрузки прерывают всю сверку без частичного успеха. Новые замечания содержат технические ID событий, публикаций и занятий без названий аудиторий. Сводка отдельно считает копии, сверки ревизий, архивирования, сопоставления защищённых занятий и архивирования с известным запретом; разнородные счётчики не выдаются за одно разбиение.

## Историческое владение внешним ID человека

Начальная инспекция и проверка выбранных полных источников проигрывают явные `personHistory` из документа учёток версии 2. Источник внешнего ID нормализуется `NFKC` и переводится в нижний регистр; само значение сравнивается точно, без смены регистра и нормализации. Этот чистый ключ вынесен из действующего реестра людей в общий помощник: правила создания, проверки карточек и сравнения снимков не изменены.

Изменение или создание, назначающее уже занятый ключ другому человеку по более раннему явному снимку, получает известную ошибку. Удаление/смена ID освобождает только владельца изменяемой карточки; остальные участники уже возникшего конфликта не теряются по последнему совпадению. Последующее исправление не отменяет нарушения при раннем событии. Равные времена внутри одной сохранённой истории используют её уже проверенный порядок; вымышленный порядок разных документов не нужен. События позже границы архива отмечаются отдельно и не создают прошлых владельцев.

Первоначальные значения внешнего ID перенесённых людей без отдельного раннего снимка не берутся из текущих карточек. До первого явного изменения они остаются неизвестными; отсутствие найденного конфликта не подтверждает полноту ранней уникальности. Для старой схемы v1 новая история не генерируется. Несколько учёток одного человека допустимы, совпадение имён не объединяет людей. Прежние связи людей с учётками и независимые исторические полномочия остаются отдельными неподтверждёнными зависимостями.

Новый инспектор загружается отдельным модулем и строит индексы известных владельцев и последнего ключа человека. Каждый входной список ограничен 25 000 записями, операции — 500 000, текст индексов — 16 МиБ. Общий сборщик замечаний ограничен 25 000 / 16 МиБ. Нарушенный порядок времени, некорректная граница, отмена и превышение пределов прерывают весь запуск без частичного успеха. В новые замечания не попадают ФИО, источник и значение внешнего ID: только технические ID события/человека. Сводка различает число проверенных явных снимков, событий с конфликтом, сопоставлений владельцев, будущих событий и перенесённых людей без раннего снимка.

## Пределы базовых проверок исторических ссылок

Базовые инспекторы назначений преподавателей, аудиторий и версий публикаций переведены на общий ограниченный сборщик замечаний и общий учёт работы. Причины, уровни и порядок прежних диагностик сохраняются; проверка назначения по-прежнему обходит текущие публикации, оставшийся журнал и архив версий в прежнем порядке. Общий промежуточный массив всех занятий больше не строится, а индексы ревизий наполняются по ходу отменяемой проверки истории.

Для каждого инспектора входные списки ограничены 25 000 записями; суммарные проверяемые копии занятий, включая повторное хранение текущих/журнальных/архивных копий, — 25 000. Операции ограничены 500 000, строковые ключи индексов — 16 МиБ, замечания — 25 000 / 16 МиБ. В базовом покрытии назначения учитывается и внутренний перебор разрешённых семестров, поэтому сочетание большого расписания с длинными назначениями не обходится без учёта работы. Проверка отмены есть до начала, при обходах и перед результатом; интерфейсу уступается управление через каждые 128 учитываемых операций. Большой скачок учтённого объёма также уступает управление перед дальнейшей работой.

Превышение пределов, отмена и ошибки не возвращают частично собранные списки замечаний как успешную инспекцию. Обёртки базовых инспекторов записывают понятную ошибку в консоль и передают отказ вызывающему запуску; отмена не выдаётся за обычную ошибку данных. Эти ограничения относятся к диагностике и не меняют создание, публикацию, архивирование или восстановление данных.

## Пределы инспекции учебных планов и снимков дисциплин

Базовая проверка планов и построение поиска исторических снимков дисциплин используют общий учёт работы. Истории планов, программ/форм обучения и периодов, карточки и история дисциплин ограничены 25 000 записями на список. Обходы строк плана, назначенных семестров и построение индексов учитываются в пределах 500 000 операций на инспектор; ключи/проекции индексов — в 16 МиБ, замечания — 25 000 / 16 МиБ. Проверка снимков дисциплин учитывает и последующие синхронные вызовы поиска: они проверяют отмену и предел, а уступку интерфейсу между строками обеспечивает вызывающий асинхронный инспектор.

Полные источники и прежние коды, уровни и порядок причин сохраняются. Ревизия 0 и старая история дисциплин остаются неподтверждёнными, текущие названия не дополняют снимки. Группа назначения без явной истории ревизий не получает ревизию из порядкового номера события: этот остаток G03 не закрыт ресурсной доработкой. Программы и формы уже проверяются по точным снимкам истории планов; новая история групп не создаётся.

Базовая инспекция планов загружается отдельным модулем в обоих запусках. Построение поиска, загрузка, отмена и превышение пределов прерывают весь запуск без частично успешной сводки. Внешняя обёртка пишет понятную ошибку, кроме отмены, и передаёт отказ; ошибки синхронного поиска также доходят до обёртки вызывающего инспектора. Сохранение, публикация, назначение учебного плана и восстановление данных не изменены.

## Хронология существования авторов действий

ID записи создания также должен быть уникален во всём аудите учёток; повторившийся ID не подтверждает основание даже при единственном `created` для этой карточки.

Начальная инспекция и проверка выбранных полных источников дополнительно сверяют время авторства с подтверждённой датой создания учётки. Основание — совпавшая дата `createdAt` карточки и единственное явное событие `created` с `previousRole: null` в том же полном источнике учёток. Импортированное создание с `importBatchId`, отсутствие даты/аудита, повторное создание или несовпадение дат не становятся таким основанием. Текущая роль не участвует в подтверждении.

Проверяются сохранённые истории учёток, людей, событий обучения, групп, дисциплин, общих периодов, программ/форм, планов, календарей, назначений преподавателей, аудиторий, версий публикаций и шаблонов расписания. У события обучения используется `registeredAt`, а не дата вступления учебного изменения в силу. Автор и время `saved-snapshot` относятся к захвату, а не исходной публикации. Действие строго раньше подтверждённого создания учётки даёт известное противоречие времени; равное время не считается ошибкой. События позже границы не используются для вывода о прежнем авторстве.

Совпадение времени существования учётки не доказывает прежнюю роль, состояние доступа, вступление в должность, общие назначения или право конкретного действия. Для старых/импортированных учёток и неполного аудита отсутствующие даты не достраиваются. Текущие ФИО, роль, настройки браузера и внешний ID не заменяют исходную историю; новые сообщения содержат только технические ID события и учётки. Прочие разделы без переданной полной истории не объявляются проверенными.

Новый модуль загружается отдельно в обоих запусках. Истории обходятся без объединённого массива; события обучения преобразуются по одному. Списки ограничены 25 000 записями, общий учёт работы — 500 000 операциями, текст ключей индексов — 16 МиБ, замечания — 25 000 / 16 МиБ. Есть отмена, уступка интерфейсу и отказ частичного результата при нарушении пределов, некорректном времени или ошибке загрузки. Сводка различает подтверждённые даты создания, просмотренные/сопоставленные события, ранние действия, отсутствие основания и события после границы.

## Внутренняя согласованность цепочек ролей

В обоих запусках полная история учёток группируется по точному `accountId` с повторным использованием уже подготовленного индекса аудита. Проверяются последовательность `previousRole → nextRole`, сохранение роли в действиях другого типа, положение события создания и совпадение последнего однозначного снимка с текущей ролью карточки. Удалённая/неизвестная учётка истории не подменяется другой по имени. Событие позже границы архива даёт отдельную ошибку; некорректное время прерывает весь запуск.

Для строгого внутреннего основания нужны единственное создание в начале с `previousRole: null`, совпадающая дата `createdAt`, отсутствие `importBatchId`, уникальные ID аудита, неубывающее время и равенство текущей ревизии числу событий учётки. Несовпадение переходов или карточки при таком основании — ошибка согласованности. Если начало/счётчик/порядок не подтверждены, расхождения остаются замечаниями на разбор; начальная роль и пропущенные события не достраиваются. Повтор ID аудита разрывает подтверждение связи соседних переходов; последняя неоднозначная запись не выбирается по последнему совпадению. История не пересортировывается по времени или ID.

Согласованная цепочка от создания означает только внутреннее соответствие сохранённых полей. Она не подтверждает статус входа, общий доступ, полномочия автора, роль в другом документе на одинаковом времени или права конкретного исторического действия и не разрешает восстановление. Учётки без раннего аудита остаются неподтверждёнными, текущая роль не становится прошлой.

Инспектор загружается отдельно; оба запуска передают индекс того же полного документа, несовместимый индекс отвергается. Списки ограничены 25 000 записями, операции — 500 000, текст индексов — 16 МиБ, замечания — 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу; ошибка загрузки, несовместимый индекс, некорректное время и превышение пределов не возвращают частичный успех. В новых сообщениях нет ФИО или значений ролей, только технические ID учётки/аудита. Сводка различает согласованные от создания и неподтверждённые учётки, просмотренные события, расхождения переходов/карточек и события после границы.

## Явные общие назначения в исторических публикациях

После проверки цепочек ролей отдельная сверка использует только внутренне согласованные учётки от явного создания и подготовленную историю того же полного документа. Для них пригоден полный снимок `assignments-changed` с сохранённой ролью преподавателя. Начальные назначения из создания не достраиваются, текущая карточка не становится прошлым снимком. Перед сопоставлением публикаций проверяется соединение последовательных известных снимков назначений и совпадение последнего известного состояния с текущей карточкой, если после него не было сброса знания. Противоречие оставляет источник на разбор, без выводов об отсутствии назначения по такой учётке.

Смена роли, создание, неоднозначная правка группы/назначений в `details-changed` и нестандартные снимки назначений у другого действия сбрасывают известный срез. Новый явный снимок после корректного сброса может снова задать области; имя/почта и статус входа сами по себе не меняют общие назначения. Эффективные области представлены точными парами ID дисциплины и группы: порядок и повторы не влияют на результат, как у действующего `hasGeneralTeachingMembership`. Пустой снимок является известным отсутствием всех назначений.

Для обычной публикации выбираются только строго предшествующие события соответствующего преподавателя с сохранённым порядком одной истории. Если пригодный снимок не содержит область занятия, это известное противоречие действующему правилу публикации. Совпадение области не подтверждает статус входа, право автора, уточняющее назначение по семестру/типу занятия или полноту ранних данных. Равное время изменения роли/назначений оставляет разбор; одновременная правка имени не меняет срез. `saved-snapshot` не задаёт время исходной публикации, поэтому назначения при захвате не подставляются в старое занятие. Отсутствующий архив версий, неполная цепочка и отсутствие пригодного снимка различаются. Публикации после границы исключены из вывода о прежнем доступе.

Сверка входит в уже отложенно загружаемый модуль цепочек ролей и используется обоими запусками. Подготовленный контекст привязан к тому же объекту полного источника, сырой контекст не попадает в отчёт. Области и эффекты событий кэшируются, курсоры двигаются отдельно по учёткам без пересортировки общей истории; равные времена повторно не сканируются для каждой пары. Списки и копии занятий ограничены 25 000, операции — 500 000, текст индексов — 16 МиБ, замечания — 25 000 / 16 МиБ. Отмена, несовместимый источник, недостающий обязательный снимок, нарушенный порядок публикаций, дубли ID, ошибка загрузки и превышение пределов прерывают весь запуск без частичного успеха. В новых сообщениях только технические ID, без ФИО и содержимого назначений.

## Сохранённые условия роли и входа при публикации

В том же отложенно загружаемом модуле оба запуска сверяют обычные публикации с внутренне согласованными цепочками учёток. Роль берётся только из строго предшествующих явных событий этой цепочки. Для автора действует существующее требование роли настройщика, для выбранного преподавателя — роли преподавателя; сохранённая несовместимая роль даёт известное противоречие. Статус входа определяется только по явному единственному полю `status` действия `status-changed` с точными значениями `active`/`blocked`. Создание и текущая карточка не задают раннюю активность.

Снимки статуса соединяются между собой и с текущим эффективным состоянием карточки, если после последнего известного статуса не было сброса. Несоединяющийся источник оставляет статус неподтверждённым, сохраняя независимую проверку роли. Явная предшествующая блокировка автора или преподавателя даёт ошибку по действующему требованию активной учётки. Условия проверяются отдельно: неопределённое время смены роли не скрывает известную блокировку, неопределённая смена статуса не скрывает известную неподходящую роль. Совпадающее время чувствительного изменения и публикации остаётся на разбор без междокументного порядка.

Повтор поля статуса, нестандартные значения, статус в действии другого типа, неизвестные поля аудита и пустое/отсутствующее описание правки деталей сбрасывают известное состояние до следующего пригодного явного снимка. Неизвестные поля и недостающие детали также консервативно сбрасывают известные общие назначения; сохраняют их только обычные известные правки имени/логина/почты, корректный описанный статус и явные снимки назначений. Это граница знания диагностического модуля, а не изменение правил записи данных. Нейтральное изменение роли сохраняет уже известный статус, но не создаёт его.

`saved-snapshot` не подтверждает условия исходной публикации: состояние при захвате не подставляется в прошлое. Публикация позже границы исключается. Авторы пустой обычной публикации тоже проверяются, преподаватели — по её занятиям. Контекст привязан к тому же полному источнику; индексы/эффекты кэшируются, курсоры идут отдельно по учёткам без пересортировки. Списки и копии занятий ограничены 25 000, операции — 500 000, текст индексов — 16 МиБ, замечания — 25 000 / 16 МиБ. Отмена, несовместимый контекст, обязательный недостающий аудит, нарушенный порядок, дубли ID и превышение пределов прерывают весь запуск без частичного успеха.

В новых сообщениях только технические ID, ожидаемое правило и вид противоречия, без ФИО и фактических значений ролей/статусов. Сводка различает сопоставления учёток, несовместимые роли, явные блокировки, неизвестные условия, равные времена, начальные снимки и публикации после границы. Это внутренняя согласованность сохранённых условий; отсутствие ошибок не подтверждает внешнее происхождение, прежние связи людей и весь набор полномочий/зависимостей восстановления.

## Сохранённый доступ авторов административных действий

После чтения всех полных источников оба запуска отдельно проверяют авторов изменений групп, дисциплин, общих периодов, программ/форм, планов, календарей, назначений преподавателей, аудиторий и шаблонов расписания. В этих действующих командах требуется активный настройщик; другие разделы с иной моделью доступа автоматически не включаются. Неподходящая сохранённая роль и пригодная явная блокировка проверяются независимо, как у публикаций. Текущий профиль автора не подставляется в прошлое, неоднозначная дата или равное время чувствительного изменения остаются на разбор. Ранние снимки дисциплин не доказывают право исходной операции по состоянию при захвате.

Поиск роли/статуса вынесен в общий источник `backupAccountAccessLookup` и привязан к тому же полному документу. Он сохраняет раздельные признаки неопределённости роли и входа, проверяет соединение статусов и их текущий конец, не выводит начальную активность при создании. Запрос назад по времени одной учётки отвергается. Административные действия собираются только как ограниченные метаданные запросов и кооперативно упорядочиваются по времени для прохода курсора. Сами исходные истории не сортируются; равное время не превращается в порядок действий разных документов и не меняет состояние учётки.

Всего просматривается до 25 000 административных записей на запуск; запросы, кооперативная сортировка, построение индексов и поиск учитываются в одном пределе 500 000 операций, текст метаданных/ключей — 16 МиБ, замечания — 25 000 / 16 МиБ. Есть отмена и уступка интерфейсу в сборе, сортировке и поиске. Несовместимый источник, обязательный недостающий аудит, некорректное время, возврат запроса назад, ошибка загрузки и превышение пределов прерывают весь запуск без частичного успеха. Сообщения не раскрывают ФИО, фактические роли/статусы и содержимое административной записи.

Индекс аудита учёток также ограничен по числу записей, работе и тексту ключей; он строится один раз на полном источнике и повторно используется базовыми проверками, пакетными операциями и проверкой ролей. Другой объект истории отвергается. Проверка ролей перенесена после чтения остальных источников, чтобы не подставлять отсутствующие позднее загружаемые документы. Внешнее происхождение, связь человека с учёткой и все остальные права/зависимости восстановления по-прежнему не объявляются подтверждёнными.

## Точность старых временных отметок

Для строгих временных выводов авторства и административного доступа требуются канонические UTC-отметки текущего формата, совпадающие с `Date.toISOString()`. Нестандартный старый формат, в том числе только календарная дата, остаётся неподтверждённым: он не превращается в фактическую полночь, не нормализуется и сам по себе не доказывает действие до создания автора или после границы. Строгая цепочка роли и дата создания автора не опираются на такие отметки. Граница самой проверки также должна быть точным каноническим моментом; формат времени манифеста исходного архива уже проверяется отдельно.

В базовой проверке выбранных источников неоднозначная отметка сохранения отделена от некорректной и точной будущей. В ссылке аудитории на старый снимок расписания неполное время не создаёт ложную ошибку сравнения с полуночью. У внешних ID человека неподтверждённое время сбрасывает известное владение только изменяемой карточки до следующего пригодного явного снимка, не создавая нового владельца и не удерживая заведомо устаревший. Известные владельцы других карточек не стираются. Каноническое событие после границы продолжает давать отдельную ошибку, а непарсируемое время прерывает соответствующий запуск. Это проверка знания, исходные строки и данные не переписываются.

## Открытые границы

Полное согласование базовых учёток/людей, групп, дисциплин и расписания с их историями/метаданными, исторические полномочия, программа группы и ранние снимки дисциплин без явной истории ревизий, все зависимости файлов, перенос счётчиков, применение и откат остаются G03. Расходящиеся ветви требуют отдельного решения без потери глобальных ревизий. Проверка временных кандидатов и сравнение 18 коллекций не разрешает восстановление. Реальные хранилища не изменяются; исходный архив сохраняется.

Автоматические тесты и браузер по ограничению пользователя не запускались. Ручная приёмка остаётся открытой в G03/A01/R12.
