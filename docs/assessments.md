# Учёт аттестаций

Первый локальный этап: экзамен, зачёт, зачёт с оценкой, практика, ВКР и курсовая работа. Практика здесь — отдельная аттестация, она не заменяет тип занятия `practice` и не меняет существующий журнал.

Контракт находится в `src/domain/assessmentTypes.ts`, чистые операции и строгий декодер — в `src/domain/assessments.ts`, локальный адаптер — в `src/data/assessmentStore.ts`. Интерфейс обращается к асинхронному `AssessmentService`, а не к localStorage. Пустое хранилище не создаёт демонстрационные экзамены.

| Операция | Кто выполняет | Результат |
| --- | --- | --- |
| `create` | Настройщик | Аттестация и основная ведомость с явно выбранным составом |
| `add-attempt` | Настройщик | Пересдача при наличии опубликованной ведомости либо повторное назначение основной сдачи после её отмены |
| `update-attempt` | Настройщик | Изменение назначения до первого сохранённого результата с записью снимка в историю |
| `cancel-attempt` | Настройщик | Отмена до первого сохранённого результата с причиной, без удаления попытки |
| `change-supervisor` | Настройщик | Замена научного руководителя текущей попытки ВКР/курсовой до первого результата по всей аттестации, с причиной и историей |
| `save-results` | Назначенный преподаватель | Черновик ведомости и снимок изменений в истории |
| `publish` | Назначенный преподаватель | Публикация полностью заполненной ведомости без перезаписи предыдущих попыток |
| `open-correction` | Настройщик | Разрешение исправления опубликованного результата с обязательной причиной |
| `save-correction` | Назначенный преподаватель | Сохранение отдельного черновика исправления |
| `publish-correction` | Назначенный преподаватель | Новая опубликованная версия результатов без перезаписи прежних |
| `read` | Действующая учётная запись | Представление по роли, уже без недоступных строк и попыток |
| `readAttemptHistory` | Настройщик | Одна страница истории назначения выбранной попытки, с повторной проверкой прав и ревизий |
| `exportStatement` | Настройщик либо назначенный преподаватель | CSV выбранной опубликованной ведомости с повторной проверкой прав и ревизий |

Для ВКР и курсовой действующий научный руководитель хранится как `supervisorId`. Назначение преподавателя каждой попытки зафиксировано в самой попытке и её истории. Заменить руководителя можно отдельной операцией до первого результата по всей аттестации; при пересдачах сохраняется уже закреплённый руководитель. Комиссия существует только у комиссионной пересдачи: председатель и хотя бы один другой член из действующих преподавателей; автор результата хранится отдельно от состава комиссии.

Одна аттестация объединяет выбранных студентов с одним ответственным преподавателем или научным руководителем. Для разных руководителей создаются отдельные аттестации с соответствующим составом, без назначения одного руководителя всей группе автоматически.

По решению от 13 ноября 2026 года допуск в MVP определяется включением студента настройщиком в состав конкретной попытки. Дополнительное разрешение или автоматический запрет по посещаемости и задолженности не требуется. При сохранении и публикации сервис по-прежнему проверяет назначенный московский момент, автора и точный состав; чужой или исключённый из попытки студент не получает результат.

## Представление раздела

Каталог включает обзор доступных аттестаций, поиск с фильтром по виду и сбросом условий. Сводка считается только по доступному пользователю представлению, независимо от поискового запроса. Основной каталог и демонстрационные примеры используют одну карточку: вид контроля, группа, период, дата последней попытки, семестр, число попыток и реквизиты программы. Студент видит личный результат, сотрудники — состояние последней ведомости.

Карточки каталога, попыток, сводки и выбора участников используют общий `Card`, выбор участников — `Checkbox`; поиск, списки и редакторы сохраняют `SearchField`, `Dropdown` и `RecordEditor`. Стили общих компонентов не переопределяются. Локальная раскладка адаптируется к узким экранам, цвета берутся из токенов темы. История показана от последней попытки к первой; правила редактирования и публикации не изменены.

## Время и результаты

Поле `room?: string` доступно в `AssessmentAttempt` и `AssessmentAttemptDraft`: аудитория обязательна для новых пересдач и комиссий, для основной попытки необязательна. Непустая строка ограничена 256 символами, без управляющих символов и пробелов по краям; форма обрезает крайние пробелы. Старые попытки без поля читаются без изменения истории, версии документа и автоматической записи.

Каждая попытка содержит календарную дату и `startsAt` в формате `HH:mm`, по московскому времени. Сохранение и публикация разрешены начиная с назначенного момента включительно. Проверка выполняется в доменной операции, а не только кнопкой интерфейса. При переносе на сервер источником текущего времени должен стать сервер: часы браузера не являются доверенным ограничением.

Экзамен, зачёт с оценкой, практика, ВКР и курсовая используют целые оценки 2–5. Зачёт — `passed` либо `failed`. `absent` означает неявку; `null` — результат ещё не выставлен. Публиковать ведомость с `null` нельзя. Итоговый средний балл журнала из этих данных автоматически не рассчитывается.

Состав аттестации фиксируется снимком ID, имени и номера зачётки. Перевод студента, изменение ФИО или состава группы не переписывают старую ведомость. Новая попытка содержит явно выбранное подмножество исходного состава. Допуск определяется этим выбором, ограничения количества пересдач автоматически не задаются.

## Целостность и чтение

Документы версий 5 и 6 хранятся под прежним ключом `bi-university-assessments-v1`, чтобы не потерять существующие данные. Версии 1–4 сначала строго проверяются, затем совместимо преобразуются в памяти в версию 5. ID, результаты, ревизия и существующие даты/авторы истории сохраняются; в версии 1 семестр и часы остаются неизвестными. Исправления не создаются из прежних оценок: для форматов 1–3 массивы `corrections` и `correctionHistory` пусты, у формата 4 они сохраняются целиком. События замены руководителя при миграции не выдумываются. Автоматической записи при чтении нет. У исходного назначения форматов 1/2 стоит `assignmentOrigin: "legacy-snapshot"`: значения взяты из сохранённого снимка, а не объявлены независимо подтверждённой первоначальной историей. Форматы 3/4 сохраняют записанные назначения без такой подстановки. Первая новая аттестация со связью с календарём переводит весь документ в версию 6; прежние записи и их события остаются без добавления вымышленных связей. Правка старой ведомости сама по себе не переводит документ 5 в 6.

### Связь с общим учебным периодом

При создании новой рабочей аттестации настройщик явно выбирает учебный год и семестр из `/admin/periods`. В `AssessmentDraft.academicPeriod` передаются только `termId` и `expectedRevision` календаря. Сервис перечитывает календарь внутри общей очереди записи; домен проверяет его схему, актуальность ревизии и существование выбранного года/семестра. Текст `draft.period` не определяет связь: итоговое название строится из проверенных реквизитов.

В `Assessment.academicPeriod` сохраняются `catalogRevision`, полные снимки `year` и `term` со стабильными ID, названиями, датами и ревизиями. Тот же снимок записан в событии `created`; строгий декодер v6 сверяет его с карточкой и текстом `period`. Другие события не меняют связь. Старые записи без поля остаются текстовыми; совпадение названий или номера семестра в зачётке не приводит к автоматическому сопоставлению. Внутренний совместимый путь создания текстовых примеров используется только явным демонаполнением; публичный сервис создания рабочей аттестации всегда требует календарь и выбранный семестр.

Изменение справочника не переписывает уже созданную аттестацию. Все попытки, исправления, представления преподавателя/студента и выгрузка сохраняют исходный снимок. Номер семестра в зачётке задаётся отдельно; дата сдачи и пересдачи не ограничивается границами выбранного семестра. Дополнительные сроки и закрытие периода этим этапом не вводятся.

Форма сохраняет ввод при внешнем изменении календаря и требует явной перепроверки. Если выбранная запись исчезла, перепроверка сбрасывает только выбор периода с понятным предупреждением, сохраняя название, состав, назначение и реквизиты зачётки. Смена года сбрасывает выбранный семестр. Недоступный календарь блокирует создание, но не чтение существующих ведомостей, сохранение/публикацию результатов, исправления и CSV. Подписка на изменения календаря обновляет список выбора в своей и соседних вкладках.

Для связанных ведомостей CSV дополнен ID, названиями, датами, ревизиями года/семестра и ревизией календаря. Текстовые ведомости сохраняют прежний набор колонок. Данные снимка берутся из ведомости, а не сегодняшнего справочника.

В архиве снимок сверяется с историей календаря на сохранённой ревизии. Индекс истории строится один раз, версии года/семестра ищутся двоичным поиском; поздние изменения не требуют совпадения с текущим названием. Отсутствующий календарь оставляет связь непроверенной, несовпадающий снимок — ошибка. В проверке выбранного набора один доступный или одинаковый в обоих источниках календарь проверяется по истории. Различающиеся версии календаря блокируют результат: выбор его записей и согласование истории остаются G03. Даже подтверждённая связь с календарём не подтверждает исторические полномочия и учебную программу группы.

Каждая новая запись в истории увеличивает общую ревизию. Команды несут ожидаемые ревизии аттестаций, учётных записей, групп, дисциплин и автора. Локальные записи выполняются через общий `executeAdministrationWrite` и Web Locks при их наличии; без Web Locks полноценная межвкладочная транзакция не гарантирована.

## Замена научного руководителя

`change-supervisor` принимает ID аттестации, нового преподавателя и причину от 2 до 500 символов одной строкой. Операция доступна только настройщику, только для ВКР/курсовой при наличии текущей попытки и до первого сохранённого результата по всей аттестации. Оценка любого участника или неявка закрывает замену; последующая очистка не открывает её. Сохранение полностью пустой ведомости не считается результатом. Новый руководитель должен быть действующим преподавателем и отличаться от текущего. Замена после первого результата не входит в согласованный MVP.

Меняются только `supervisorId` и преподаватель текущей попытки. ID, номер, состав, дата/время и аудитория сохраняются; отменённые попытки не переписываются. Будущие назначения наследуют действующего руководителя. Прежний преподаватель теряет доступ к текущей попытке, новый получает его; доступ к собственным прежним отменённым назначениям сохраняется. Обычное редактирование назначения не обходит этот процесс.

Событие `supervisor-changed` содержит снимок назначения, `previousSupervisorId`, причину, автора и время. Декодер воспроизводит руководителя на каждом шаге истории, проверяет соответствие прежнего ID, смену только преподавателя, отсутствие любого ранее сохранённого результата и согласованность текущего руководителя. Старые назначения остаются привязаны к прежнему руководителю. История назначения показывает прежнего и нового преподавателя, причину и дату по Москве; она загружается отдельными страницами для настройщика.

Сервис повторно проверяет права и ревизии в общей очереди записи. Замена и первое сохранение результата не могут затереть друг друга: проходит одна команда, другая требует свежего контекста. В интерфейсе используется существующий поиск преподавателя с пустым placeholder и подтверждение с причиной; устаревший контекст блокируется без автоматического принятия нового руководителя. Возможность замены возвращается только настройщику как `manageableSupervisorAssessmentIds`.

Инспектор архива и проверка зависимостей учитывают ссылки на прежнего руководителя; сравнение истории знает поле `previousSupervisorId`. Наличие внутреннего аудита по-прежнему не подтверждает исторические полномочия независимо от источника и не снимает блокировку восстановления.

## Редактирование и отмена попытки

Настройщику доступны дата, московское время, аудитория, ответственный преподаватель и состав комиссии до первого сохранённого результата. Назначенное время уже может наступить. Состав студентов, вид попытки и научный руководитель при этой правке не меняются. Неизвестная аудитория старой попытки не заполняется предположением; для новых пересдач аудитория по-прежнему обязательна.

Граница определяется всей историей: любая сохранённая оценка 2–5, зачёт, незачёт или неявка закрывает редактирование назначения и отмену, даже если позже все отметки очищены. Полностью пустой снимок результатов не закрывает эти действия. Опубликованные и отменённые попытки закрыты. Проверка выполняется доменом внутри общей очереди записи, а не только по состоянию кнопки. Настройщик получает `manageableAttemptIds` и страницы истории через отдельный запрос; это представление для интерфейса, сервис заново проверяет исходные данные и полномочия при выполнении команды.

Решение от 13 ноября 2026 года: после первого результата изменение назначения запрещено в MVP, включая дату, время, аудиторию и преподавателя. Отдельное исправление назначения не вводится. Исправление опубликованной оценки выполняется через разрешение настройщика и новую версию ведомости, сохраняя первоначальное назначение.

`attempt-updated` хранит снимок назначения; предыдущее значение остаётся в более раннем событии. Проверка истории использует актуальное на каждом шаге назначение преподавателя и даты/времени и не допускает задним числом правку после первого результата. При отмене обязательна причина от 2 до 500 символов одной строкой; сохраняются время и автор, ID, состав и история попытки. В карточке есть свёрнутая история назначений с постраничным просмотром.

После отмены создаётся новая запись с новым ID и следующим номером. Если основной опубликованной ведомости ещё нет, «Назначить заново» сохраняет вид основной сдачи. При наличии прежней опубликованной ведомости доступны обычная и комиссионная пересдачи; отменённая запись не меняет свой вид и не удаляется. Дата может быть раньше отменённого назначения, но не раньше предыдущей опубликованной попытки. Номер записи не определяет число разрешённых сдач: такие правила вуза пока не заданы. Прежние опубликованные результаты остаются в зачётке.

Студент видит явное состояние «Отменено» без ожидания результата, внутренних причин и авторов отмены. Преподаватель видит состояние своей назначенной попытки; историю управления получает только настройщик. При устаревшем источнике правка/подтверждение блокируются с сохранением ввода. Конкурирующие правка, отмена и сохранение результата проверяют одну ревизию: устаревшая команда не перезаписывает победившую операцию.

## Исправление опубликованного результата

Настройщик разрешает исправление конкретной опубликованной попытки с причиной от 2 до 500 символов одной строкой. На одну попытку одновременно существует один черновик. Он начинается с последней опубликованной версии результатов, а не с пустой ведомости. Назначение, состав, научный руководитель, комиссия, дата сдачи и номер попытки не меняются. Исправление не является пересдачей; допуск, число попыток и замена руководителя этим процессом не определяются.

Редактировать и публиковать исправление может только действующий назначенный преподаватель. Настройщик, председатель и члены комиссии не получают право выставлять оценку только из-за своего участия. Используется существующая форма ведомости с поиском, страницами, сохранением ввода и явным разрешением конфликтов после внешнего изменения. Закрытое другим изменением исправление не открывается повторной перепроверкой. Публиковать можно полностью заполненную версию, в которой изменён хотя бы один результат; шкалы и отдельная неявка сохраняются.

Первоначальная публикация остаётся в исходной попытке и `history`, исправления и их снимки — отдельно в `corrections` / `correctionHistory`. Общая ревизия равна сумме событий двух историй. Декодер проверяет разрешение, последовательность версий, автора и время каждой записи, неизменный состав, наличие всех снимков и соответствие опубликованному состоянию. Все команды используют ту же очередь записи и проверку ревизий; время не может предшествовать исходной публикации или последнему действию документа.

До публикации исправления `read` возвращает студенту прежний результат; после публикации — последний опубликованный результат этой попытки. Черновики, причины, авторы разрешений и история исправлений студенту не передаются. Зачётка использует ту же проекцию. У сотрудника в снимке находятся только активные черновики и краткие реквизиты опубликованных исправлений, без полного аудита сохранений. В карточке доступны разрешение, редактирование, публикация и список опубликованных версий с CSV.

`exportStatement` без `version` выдаёт актуальные опубликованные результаты; с положительным целым `version` — выбранную опубликованную версию, где 1 означает первоначальную. Версия указана в имени файла. Даты сдачи и преподаватель сохраняются, экспортные реквизиты зачётки берутся из текущих реквизитов аттестации, как и в обычной выгрузке. Черновики и чужие ведомости не экспортируются. Предыдущие результаты остаются в исходном документе, независимо от того, какая версия показана интерфейсом.

Инспектор архива проверяет авторов и время исправлений; административная проверка сообщает о недоступном ответственном преподавателе активного исправления. Сравнение резервных копий дополнено отдельными коллекциями исправлений и их аудита. Выбор версии не объединяет эти коллекции автоматически и не снимает блокировку восстановления при неподтверждённых правах или учебной области.

## Обычное демонаполнение

Названия новых демозаписей используют UTF-8 и тире вместо средней точки: «Экзамен — опубликованный пример», «Экзамен — черновик»; период — «Демонстрационный учебный период». Для ранее сохранённых записей адаптер после строгой проверки документа исправляет при чтении только точные известные повреждённые литералы заголовка и периода на стабильных ID `demo-assessment-v1:<kind>:published|draft` с совпадающим видом. Произвольные заголовки, периоды, пользовательские записи, результаты, попытки и история не заменяются. Чтение не пишет в localStorage и не меняет ревизию; исправления сохраняются при следующей успешной штатной записи документа. Повторный импорт без новых записей также не пишет. История этих текстовых демозаписей не содержит заголовков и снимков календаря, поэтому её значения остаются неизменными; повреждённая структура или история по-прежнему отклоняется декодером.

Кнопка «Наполнить демоданными» добавляет в обычный раздел аттестаций 12 ведомостей-аттестаций всех шести видов (по опубликованному примеру и черновику), всего 18 попыток. Экзамены включают основную сдачу, пересдачу и комиссию; зачёты — пересдачу после незачёта. Используются действующие Анна Смирнова, Елена Волкова, группа студентки и реальные дисциплины из назначений преподавателя. Реквизиты зачётки включают семестры, часы и факультатив. Даты попыток уже наступили относительно момента импорта, поэтому назначенный преподаватель может редактировать черновики сразу. Студент видит только опубликованные личные результаты; редактирование результатов ему недоступно.

Если для комиссии нет второго действующего преподавателя, явный импорт добавляет учётную запись «Иван Петров (демо-комиссия)» с уникальными ID и логином и записью в истории учётных записей. Существующие аккаунты не заменяются и не разблокируются. При недоступности демо-участников, назначений или группы выводится предупреждение вместо подмены ссылок. Член комиссии не получает право заполнять ведомость вместо ответственного преподавателя.

Импорт использует общий административный write-lock, повторно читает документы внутри блокировки, создаёт историю штатными доменными командами и проверяет итог строгим декодером перед записью. Стабильные ID позволяют дополнять только отсутствующие аттестации: повторный импорт не заменяет ни пользовательские записи, ни изменённые демо-черновики. Повреждённые документы не перезаписываются. Аккаунт члена комиссии сохраняется перед ссылающимися на него ведомостями; если запись аттестаций не удалась, повторный импорт использует уже созданный аккаунт без дубликата. Чтение пустого раздела само по себе ничего не добавляет. Изолированные примеры `?example=1` остаются отдельным режимом, для обычного демонаполнения он не нужен.

## Зачётка и примеры

В профиле студента вкладка «Зачётка» показывает последний опубликованный личный результат по каждой аттестации. Зачёты и экзамены разделены на две колонки; практики, курсовые, факультативы и ВКР — отдельные разделы. Номер семестра выбирается в URL; на телефоне строки показаны карточками. Часы и семестр задаются явно в `recordBook`, а не извлекаются из описания дисциплины. Факультативность независима от формы контроля.

Настройщик заполняет реквизиты при создании или отдельной командой `update-record-book`. Изменения семестра, часов и раздела аудируются и не переписывают оценки или попытки. Старые записи без этих данных остаются в разделе «Семестр не указан».

Изолированный режим `?example=1` показывает 56 вымышленных аттестаций за 4 курса и 8 семестров, включая пересдачи и комиссию. Он доступен по ссылкам «Посмотреть примеры за 4 курса» в аттестациях и «Посмотреть пример за 4 курса» в зачётке; примеры только для чтения и не записываются в хранилище. ID примеров не используются для реальных команд сохранения.

Декодер проверяет структуру, уникальность ID, состав, оценки, хронологию, научного руководителя, комиссию и согласованность истории с текущими результатами. Повреждённый документ не заменяется пустым и не перезаписывается при ошибке чтения или сохранения.

Преподавателю возвращаются только назначенные ему попытки и их участники. Студенту — все попытки, в которых он участвует, включая будущие черновики и отменённые назначения. Сохраняются дата, время, аудитория (если известна), вид попытки, преподаватель и комиссия. У черновика и отменённой попытки для студента всегда `results: []`, у опубликованной — только собственная строка. `studentIds` и состав ограничены самим студентом; чужие попытки отсутствуют. Полная история не входит в `AssessmentSnapshot` ни для одной роли. Историю назначения получает только настройщик отдельным запросом; у преподавателя и студента нет `manageableAttemptIds`, у студента также нет внутренней причины и автора отмены. Справочники выбора студентов доступны настройщику. Смена учётной записи скрывает предыдущий снимок; фоновое обновление сохраняет ввод формы, временно блокируя сохранение до проверки свежих данных.

В открытой форме пересдачи перепроверка принимает новые ревизии только при неизменном исходном назначении, составе и попытках этой аттестации. Если другой настройщик уже добавил и опубликовал следующую попытку, обновление проверки не превращает прежний черновик формы в ещё одну пересдачу. Исчезнувший источник или изменённая аттестация оставляют ввод и прежний контекст проверки на месте; требуется проверить аттестацию и открыть форму заново. Изменение независимых реквизитов зачётки или другой аттестации допускает перепроверку. Семантическое сравнение не зависит от порядка свойств JSON; общие проверки ревизий в сервисе сохраняются.

Это локальная демонстрационная изоляция интерфейса. Данные лежат в браузере; защищённое хранение, вход и проверку прав каждой операции должен обеспечить сервер. Поля `actorId` и ревизии из запроса не заменяют серверную сессию, права и атомарную проверку зависимостей.

## Постраничная история назначения

`readAttemptHistory` принимает `AssessmentCommandContext`, пару `assessmentId` / `attemptId` и положительный целый `page`. Повторно проверяет действующую учётку настройщика, все ревизии и принадлежность попытки указанной аттестации. Возвращает `revision`, `items`, `total`, `page`, `pages`; размер страницы фиксирован — 20 записей. Страница за концом списка ограничивается последней. Порядок — от новых событий к старым по исходной последовательности аудита, включая события с одинаковым временем.

Это история назначения: создание аттестации/попытки, изменение назначения и отмена. Сохранение оценок, публикация и изменение реквизитов зачётки остаются в полном документе аудита и не попадают в этот ответ. Проекция содержит автора, время, назначение, комиссию, причину отмены и отметку происхождения старого снимка; оценки и полный состав студентов не передаются. Копируются только поля выбранной страницы, источник не меняется.

Закрытый блок не запрашивает историю. При раскрытии и переключении страниц интерфейс показывает загрузку, ошибку и повторную попытку. Ответ прежнего запроса скрывается при смене страницы, учётки, снимка данных или блокировке обновления; отложенный ответ после закрытия или размонтирования не применяется. Пагинация использует отдельные запросы, а не полный аудит в памяти компонента.

Локальный адаптер по-прежнему читает и строго проверяет весь JSON-документ в браузере: это ограничение текущего хранилища, а не серверная пагинация. Контракт ограничивает объём ответа и позволяет HTTP-адаптеру получать страницу из базы с теми же проверками, порядком и ревизией. Авторизацию по серверной сессии и индексы базы нужно реализовать на сервере.

## Экспорт опубликованной ведомости

В опубликованной попытке у сотрудника доступна кнопка «Скачать CSV». Формат использует общий `createCsv`: UTF-8 с BOM, разделитель `;`, CRLF, экранирование кавычек и защита текстовых ячеек от интерпретации как формул. Новые библиотеки не требуются. В строках — только явно выбранные участники этой попытки, их ФИО и зачётки из зафиксированного состава, результаты, реквизиты аттестации и зачётки, дата/время по Москве, аудитория, ответственный преподаватель или руководитель, комиссия и стабильные ID. Неявка, незачёт и оценка 2 сохраняются разными значениями. Неизвестные семестр, часы и номер зачётки остаются пустыми.

Контракт `AssessmentStatementRequest` несёт ID аттестации/попытки и существующий контекст ревизий. `AssessmentStatementFile` содержит имя файла и CSV без DOM-зависимостей; браузерное скачивание выполняется существующим `downloadBlob`. Локальный адаптер заново читает документ и справочники, проверяет действующую учётку и ревизии через общий `requireAssessmentActor`. Преподаватель скачивает только назначенную ему попытку; членство в комиссии само по себе не даёт это право. Студент, черновик и отдельный демонстрационный пример полного экспорта не получают. Экспорт не пишет в хранилище, не создаёт новую ревизию или историю и не меняет результаты.

При обновлении источника либо уходе со страницы отложенный ответ не запускает скачивание. Ошибки подготовки и скачивания отображаются рядом с действием и записываются в console.error. Имена студентов берутся из снимка ведомости; имена сотрудников — из доступного актуального справочника. При отсутствии имени сотрудника явно показывается его ID, исторические ФИО не восстанавливаются предположением. Существующая история предыдущих попыток экспортируется отдельно выбором соответствующей ведомости.

## Проверка резервных копий

Общий инспектор архива выделяет «Аттестации и ведомости» в отдельную область. Он читает документы версий 1–6 через общий строгий декодер, проверяет состав, результаты, пересдачи, комиссию, отмену, замену руководителя, разрешения исправлений, снимки периодов и согласованность обеих историй. Миграции выполняются только в памяти; исходный ключ и текст архива не переписываются. Для назначений старого формата, полученных из снимка, есть отдельное замечание о неподтверждённом происхождении исторических значений. Неизвестный или повторяющийся ключ и повреждённая схема дают ошибку, а не пустую ведомость.

Ссылки на группу, дисциплину, весь зафиксированный состав студентов, преподавателя, научного руководителя, комиссию, создателей, опубликовавших и авторов истории сверяются только с архивными справочниками по ID. Отсутствующий справочник означает неподтверждённую связь, отсутствующий ID в читаемом справочнике — ошибку. Встроенные группы, совпадение ФИО и текущие данные браузера не подставляются. Даты сохранённых действий сверяются с завершением архива; будущая дата назначенной сдачи сама по себе допустима.

Наличие ID не доказывает исторические права и состав группы. Текущая роль, блокировка или перевод студента не используются для восстановления прошлых полномочий. У непустой аттестации отдельно отмечены неподтверждённые исторические полномочия и учебная область: связь с календарём проверяется для v6, но независимого источника назначений и программы группы пока нет. У старых текстовых ведомостей связь с календарём также остаётся неподтверждённой. По согласованной политике эти замечания блокируют весь архив. Даже пустой корректный документ не даёт разрешение на запись: остаются итоговая проверка, разрешение конфликтов и авторизация восстановления. Применение и объединение ведомостей не включены.

Проверка поддерживает отмену, не читает локальные хранилища и не изменяет оценки, ревизии или аудит. В техническом отчёте — коды замечаний и ID без названий аттестаций, ФИО, результатов и фрагментов повреждённого JSON.

### Конфликты аттестаций и истории

`backupAssessmentComparison` сравнивает отдельно карточки аттестаций и события истории по точному ключу документа и ID. Внутри карточки сохраняется целиком состав, набор попыток, результаты, комиссия и отмена; события дополнительно сравниваются по своему ID и ссылкам на аттестацию/попытку. Каждый источник сначала проходит общий строгий декодер вместе со своей историей. Повреждённый, противоречивый или неоднозначный документ не считается пустым и не сравнивается частично. Отсутствующая сторона учитывается как записи только в архиве либо только в браузере, без создания ID или подстановки демонстрационных данных.

Совместимые форматы 1/2 сравниваются в представлении общего декодера: неизвестные реквизиты остаются неизвестными, производное назначение имеет `assignmentOrigin=legacy-snapshot`. Отличие этой метки показывается отдельно. Это совместимое чтение, а не подтверждение отсутствующей первоначальной истории; исходные строки и версии не перезаписываются. Различие метаданных документа также остаётся в общем сравнении локальных данных.

В техническом отчёте и списках различий находятся только ID, счётчики и названия изменённых полей. Явный просмотр конфликта показывает значения двух версий через общий сервис: повторная проверка настройщика, SHA-256 файла и неизменности текущих источников. После полного просмотра можно выбрать версию как черновик этой проверки. Дополнительные неизвестные поля или слишком большой просмотр не дают отметить версию просмотренной; частичный текст не выдаётся за полный. Смена учётки, исходных данных или проверяемого файла делает прежний просмотр недействительным.

Выбор карточки не выбирает автоматически её историю и исправления; более поздняя дата и большая ревизия не дают приоритета. Сравнение версии 2 содержит четыре части: аттестации, исходный аудит, исправления и аудит исправлений. Старый результат версии 1 остаётся читаемым без дополнения отсутствовавших разделов. Применение, объединение выбранных карточек с событиями и ревизией документа требуют отдельной итоговой проверки. Неподтверждённые полномочия и учебная область продолжают блокировать весь архив даже после просмотра и выбора версий. Скачивание полного отчёта проверяет полноту всех частей сравнения и не включает показанные значения или черновик выбора.

## Административная проверка зависимостей

Раздел `/admin/checks` включает категорию «Аттестации с недоступными связями». Чистый доменный модуль `assessmentDependencies` проверяет ID группы, необязательной дисциплины, всего зафиксированного состава студентов, руководителя, преподавателей, комиссии, создателей и опубликовавших попытки, а также авторов истории. Ссылки на одну отсутствующую учётку внутри аттестации не дублируются. Совпадение ФИО не заменяет исходный ID.

У неопубликованной попытки заблокированный преподаватель или смена его роли отмечаются как проблема заполнения ведомости. Изменённые учётки комиссии и незавершённая ведомость архивной группы требуют ручной проверки. Для опубликованных попыток сегодняшние роли, блокировки и архив группы не используются для оценки прошлого назначения. Перевод, выпуск и блокировка студента не удаляют его из зафиксированного состава; назначения обычных пар не заменяют отдельное назначение ответственного за аттестацию.

Локальный `administrationChecksService.list` после проверки прав настройщика читает строгий документ аттестаций и возвращает его ревизию в `versions.assessments`. Отсутствующий документ означает отсутствие внесённых аттестаций, повреждённый — ошибку всей проверки без подстановки пустых данных. Проверка не пишет в хранилище, не меняет бизнес-правила операций с учётками и не доказывает исторические полномочия. Поиск, важность, счётчики и страницы работают через общий контракт административной проверки.

Из замечания открывается точная аттестация, а при недоступном ответственном преподавателе — его учётка. Проверенный локальный адрес возврата сохраняет фильтры и страницу отчёта. Он поддерживается общими `ChecksContextLink` и `AdministrationReturnNotice`; обычный вход в аттестации не показывает дополнительного уведомления. Изменения источника и возврат фокуса обновляют проверку; прежний успешный результат скрывается до завершения актуального запроса.

## Следующие этапы

Связь с учебными периодами и дополнительные сроки остаются в U09 рабочего плана. Изменение назначения и замена научного руководителя после первого результата исключены из согласованного MVP. Допуск определяется включением в состав попытки; отдельное согласование допуска снято с очереди. Подтверждение исторических полномочий, учебной области, согласованности выбранных справочников с историей и применение архива остаются частью G03; инспекция схемы не заменяет эти этапы.

## Проверка выбранного набора аттестаций в архиве

`reviewBackupAssessmentSelection` проверяет только внутреннюю согласованность четырёх коллекций документа: карточек аттестаций, основной истории, исправлений и аудита исправлений. Различающиеся значения одного ID требуют явного выбора источника; дата и ревизия не дают приоритета. Совпадающие записи берутся один раз, записи только из архива и только из браузера сохраняются в проверяемом наборе. Неподдерживаемые ключи, повторяющиеся документы и повреждённая схема блокируют проверку вместо подстановки пустого источника.

Выбранные карточки не пересобираются по отдельным оценкам. События располагаются по сохранённому времени, а при одинаковом времени сохраняется порядок подходящих событий обоих источников внутри одной аттестации или попытки исправления. Независимые аттестации не связываются искусственным порядком. Противоречащие последовательности одной области блокируются; порядок аудита не угадывается. Ревизия кандидата равна числу выбранных событий обеих историй и показывается отдельно от исходных ревизий. Полный кандидат проходит строгий декодер формата 5; он выявляет несовместимость состава, попыток, результатов, назначений, публикаций и исправлений с историей. Наружу возвращаются только статус, счётчики и сообщения без ФИО, оценок и причин.

Сервис `reviewAssessments` использует только внутренний черновик выбора, доступный после полного просмотра конфликта. Он повторно проверяет учётку, исходный файл по SHA-256 и весь снимок localStorage, а также ревизию черновика до и после асинхронной операции. Смена файла, исходных данных или выбора сбрасывает результат; события изменения аттестаций также перепроверяют открытый просмотр. Проверка ограничена общими бюджетами и поддерживает отмену.

Сервис дополнительно проверяет наличие ссылок выбранного набора по точным ID в карточках учёток, групп и дисциплин. Проверяются участники, преподаватели, комиссия, авторы обеих историй, прежние назначения и научные руководители. Совпадающие карточки и записи только из одного источника доступны для этой проверки; разные значения одного связанного ID требуют полного просмотра и выбора версии в соответствующем сравнении справочника. Различия не связанных с ведомостью карточек не заставляют выбирать все записи вуза. Отсутствующий справочник, отсутствующий ID и неразрешённый конфликт различаются; повреждённый или неподдерживаемый источник не заменяется другой версией, встроенными примерами или совпадением имён.

`AssessmentReferenceReview` имеет область `assessment-reference-presence`: найденный ID подтверждает только наличие ссылки. Текущие роли, блокировки и учебные назначения не подтверждают прошлое право на ведомость и не отменяют исторические результаты. Предпросмотр замечаний использует общий поиск и страницы различий, показывает технические ID без ФИО, оценок и причин. При изменении любого выбора, исходных данных или полномочий результат скрывается; требуется повторная проверка.

Результат не попадает в сохранённый технический отчёт и не разрешает восстановление. Подтверждение исторических полномочий, периодов, согласованности выбранных справочников с их историей и остальных зависимостей остаётся отдельным этапом G03. Документ-кандидат не передаётся UI и не записывается в хранилище.

HTTP-адаптер должен сохранить смысл команд, стабильные ID, историю и представления по ролям. На сервере нужны транзакция с аудитом, проверки ревизий/ETag и зависимостей, уникальные ограничения, идемпотентность повторных запросов, поиск и пагинация. Проверка времени и авторства должна выполняться по серверным данным.
