# BIUniversity — рабочий проект

Ветки одного репозитория хранят разные части проекта:

- `master_main` — workspace, настройки pnpm и планы работ.
- `master2` — исходники frontend, подключённые как submodule `frontend`.
- `main` — production-сборка для GitHub Pages.

## Первый запуск

Проверенная среда: Node.js 24 и Corepack с pnpm 12.14.0.

```powershell
git clone --branch master_main --recurse-submodules https://github.com/111111N/BIUniversity.git
cd BIUniversity
corepack pnpm install --frozen-lockfile
corepack pnpm run dev
```

Для уже существующего клона:

```powershell
git submodule update --init --recursive
corepack pnpm install --frozen-lockfile
```

## Проверки и сборка

```powershell
corepack pnpm run typecheck
corepack pnpm run lint
corepack pnpm run test
corepack pnpm run build
```

Сборка для текущего адреса GitHub Pages:

```powershell
corepack pnpm run build --base=/BIUniversity/
corepack pnpm --filter frontend run check:build dist /BIUniversity/
```

Результат находится в `frontend/dist`. В ветку `main` публикуются содержимое
этой папки и копия `index.html` под именем `404.html` для прямых ссылок SPA.
Исходники и настройки workspace публикуются в свои ветки отдельно.

`check:build` проверяет manifest, наличие начальных и отложенных файлов,
базовый путь HTML, статические циклы чанков и зависимости vendor от страниц.
Он также показывает суммарный JS/gzip оболочки. После обычной сборки для `/`
можно вызвать `corepack pnpm --filter frontend run check:build` без аргументов.
Это проверка артефактов; прямые переходы SPA и поведение браузера проверяются отдельно.

В среде с ограниченным доступом esbuild к родительским каталогам конфигурацию
можно загрузить средствами Node.js 24:

```powershell
corepack pnpm run build --configLoader=native --base=/BIUniversity/
```

Актуальные результаты проверок и их ограничения сохраняются в
[отчётах](plans/archive/README.md). ESLint охватывает исходники frontend,
настройки сборки и проверяющие скрипты; номера старых прогонов не заменяют новый запуск.

Локальный сборник `collected_code.txt` исключён из Git. Он остаётся на диске
и не публикуется вместе с исходниками.

Настройщику доступна «Резервная копия данных» под выбором демонстрационной
учётной записи (`/admin/data`). Выгрузка JSON содержит сохранённые данные всех
пользователей этого адреса и вложения из трёх IndexedDB-хранилищ. Она не меняет
исходные записи и не запускает миграции. Файл содержит личные данные и переписку,
не зашифрован; перед выгрузкой нужно завершить редактирование в других вкладках.
Чтение согласовано внутри каждого файлового хранилища, общего моментального
снимка между ними нет. Пределы: 64 МиБ вложений, 16 МиБ текста, 25 000 файловых
записей и 128 МиБ итогового JSON. Временные черновики, несохранённые формы и
данные других адресов не входят. Восстановление и личная выгрузка ещё не реализованы.

В этом же разделе вкладка «Проверить файл» проверяет административный JSON v1
на устройстве и сравнивает сохранённые записи с текущими: совпадения, различия
содержимого, записи только в архиве/браузере, различия структуры хранилищ.
Сравнение ничего не записывает и не запускает восстановление. Проверка формата,
размеров и base64 не заменяет проверку учебных связей и внутренних версий;
SHA-256 выбранного файла не подтверждает его автора или подлинность.

В предпросмотре отдельно проверяются схемы учёток, групп, дисциплин и расписания
существующими декодерами приложения, основные ссылки между ними и сохранение
текущего ID действующего настройщика. Отсутствующие документы не заменяются
данными браузера. Ссылки на встроенные группы помечены зависимостью от версии
приложения; неизвестные версии ключей не пропускаются молча. Ошибки и непроверенные
области выводятся отдельно. Эти частичные проверки не разрешают восстановление.
