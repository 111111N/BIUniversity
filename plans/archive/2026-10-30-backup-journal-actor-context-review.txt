СОХРАНЁННЫЙ КОНТЕКСТ АВТОРА СОБЫТИЯ ЖУРНАЛА
Дата: 30 октября 2026
Область: G03, чтение архива перед возможным восстановлением

1. ЧТО ИЗМЕНИЛОСЬ
Сохранённые внутри события роль и учебные назначения автора сверяются
с текущим контрактом записи журнала: преподаватель с назначением на точную
пару ID дисциплины и группы списка. Это диагностика согласованности
утверждений внутри архива, а не аутентификация или подтверждение реальных
полномочий на дату события. Правила исходной версии могут отличаться.
Рабочая авторизация и бизнес-логика записи журнала не менялись.

Различаются четыре результата для каждого события читаемого списка:
- сохранённая роль и пара назначения соответствуют текущему контракту;
- явно сохранённая роль или назначения расходятся с ним;
- роль или назначения не сохранены, контекст неполон;
- назначения нельзя сопоставить, потому что область списка не определена.
Расхождение или неполный контекст создают замечание для проверки с ID события.
Они не объявляются доказанным неправомерным редактированием и не превращают
читаемую схему истории в структурную ошибку.

2. ГРАНИЦЫ И ПРОВЕРКИ
Роль и назначения из учётки на момент выгрузки не заполняют старое событие.
Текущий преподаватель занятия не подменяет сохранённого автора и не считается
самостоятельным доказательством исторических прав. Конкретное назначение
на лекцию/практику/лабораторную остаётся отдельной задачей.
Совпадение ID автора с учёткой и согласованность его сохранённых утверждений
проверяются независимо: даже согласованный контекст не делает автора
аутентифицированным и не скрывает отсутствие его ID в документе учёток.

Дисциплина и группа должны находиться в одном сохранённом назначении;
группа одного предмета не объединяется с дисциплиной из другой записи.
ID сравниваются буквально, без нормализации и разбиения составных строк.
Явный пустой список назначений отличается от отсутствующего поля.
Роль не выводится из списка назначений. При неизвестной области назначения
автора не используются, чтобы угадать дисциплину или группу списка.
Уже существующее замечание области не дублируется для каждого такого события.

Проверяются события отметок, оценок, состава и демонстрационного заполнения.
При одинаковом ID автора каждое событие проверяет собственный контекст:
он мог меняться, поэтому результаты не кэшируются только по ID человека.
Нечитаемый список не проверяется по частичному читаемому фрагменту.
Прямой вызов проверки схем без каталогов явно сообщает, что контекст
не сверялся с контрактом записи.

3. ИНТЕРФЕЙС И СОХРАННОСТЬ
В существующей сводке истории показаны числа согласованных, расходящихся,
неполных событий и событий с неопределённой областью. Это не число авторов
или подтверждённых разрешений. При частично нечитаемой области счётчики
относятся только к читаемым спискам; общий счётчик событий по-прежнему скрыт.
Замечания используют ключ исходного списка и ID события, включаются
в пагинацию и полный JSON-отчёт. Имена, исходные назначения и значения
ячеек не включаются в новые сообщения. События и учётки не изменяются.
Сводка явно говорит: совпадение — сверка утверждений, а не реальных прав.

Чистая функция использует только событие и область из каталогов архива,
не читает живые хранилища, не заменяет автора и не создаёт назначений.
Отмена поддерживается внутри списка событий, назначений одного автора
и большого списка групп. 300 замечаний сохраняются без обрезания.
Новых библиотек, миграции, записи и восстановления нет.

4. ПРОВЕРКА
Точечный профиль: 61 тест в трёх файлах прошёл; TypeScript и общий ESLint
прошли. Покрыты разные роли, неполный контекст, пустые и чужие назначения,
раздельные пары ID, несколько назначений, буквальные ID, неизвестная область,
разные контексты одного автора, все типы события, отсутствие подстановки
из текущей учётки/расписания, независимость проверки ID, нечитаемый список,
неизменяемый вход, 300 замечаний и отмена в трёх видах больших списков.
Общий профиль: 544 теста в 23 файлах прошли, включая остальные области
архива, JSON-отчёт, SSR и существующий journalStore.
SSR отличает неполный контекст от ошибки схемы и показывает ID события;
полный отчёт сохраняет код замечания и оговорку о непроверенных реальных
полномочиях без раскрытия имён и изменения архивных или текущих данных.
Полный набор портала повторно не запускался.
Production-сборка с базой /BIUniversity/ прошла. check:build подтвердил
97 записей манифеста и 122 файла; browserRuntimeChecked=false.
Проверки diff и планов прошли: 52 архивных хеша, 7 рабочих планов,
74 Markdown-ссылки и 7 кратких пересказов.

5. ЧТО ОСТАЛОСЬ
Определить проверяемый источник исторических ролей, полномочий и назначений
для конкретного занятия, состояния обучения и состава группы на его дату.
Нужны решения для неполного контекста и расхождения с текущими правилами,
с учётом версии исходного приложения. Ни одно из этих состояний не выбирает
значение для восстановления и не разрешает импорт.
Ручная приёмка статусов, счётчиков, длинных ID, тем, телефона и клавиатуры
остаётся в активном G03. Браузер и Computer Use не использовались.
Коммитов, отправки в Git и публикации нет. Снимок 52 документов
от 28 октября не изменён.

КРАТКИЙ ПЕРЕСКАЗ
История различает согласованный, расходящийся и неполный контекст автора,
не подставляя текущие роли и назначения. Это проверка сохранённых утверждений;
реальные исторические полномочия остаются отдельной задачей.
