ПРОВЕРКА И ПРЕДПРОСМОТР РЕЗЕРВНОЙ КОПИИ
Дата: 28 октября 2026
Область: G03, продолжение административной выгрузки. Применение восстановления не добавлено.

1. РЕЗУЛЬТАТ И ИНТЕРФЕЙС
В /admin/data два режима общего переключателя: «Скачать» и «Проверить файл». Выбранный файл проверяется локально, без отправки на сервер. Видимая подпись показывает лимит 128 МиБ; проверка запускается отдельной кнопкой. Есть прогресс, отмена, ошибки с повторной попыткой, защита от параллельного запуска и отмена при уходе со страницы. Нажатие текущей вкладки не отменяет работу. Переключение режима отменяет текущую операцию; панели сохраняют своё состояние, включая нативный выбор файла.

После проверки показаны имя/дата архива, пять показателей сравнения, различия списком по 20 на страницу. Длинные ID и имена переносятся; содержимое записей и переписка в отчёт не выводятся. Поверхности и кнопки используют общие токены тем, основные цели взаимодействия не меньше 44 px. Реальная визуальная приёмка не проводилась.

Сообщения различают проверку формата и восстановление. Записей и кнопок для применения, перезаписи или удаления нет. Совпадающие ID не считаются автоматически одинаковыми данными. Записи только из браузера не объявляются кандидатами на удаление. Подробные ограничения и отпечаток файла находятся в раскрываемом блоке.

2. ПРОВЕРКА НЕДОВЕРЕННОГО JSON
Отдельный доменный валидатор принимает административный формат bi-university-local-backup v1. До чтения текущих источников проверяются формат, область, версия, разрешённые поля, метаданные/хронология, перечень трёх баз, обязательные хранилища, keyPath и индексы, первичные ключи, типизированные значения и итоги.

Дубли ключей localStorage, баз, хранилищ, индексов, полей типизированного объекта и первичных ключей в одном хранилище отклоняются. Посторонние ключи localStorage и неизвестные базы не принимаются. Неизвестные теги и дополнительные поля типизированных значений не игнорируются. У отсутствующей базы не может быть записей.

У Blob/File проверены типы метаданных, размер, канонический алфавит/длина/паддинг base64, включая значащие биты последнего символа. Итоговые количества вычисляются заново и сверяются с заголовком. Проверяются лимиты двоичных данных, текста, записей, глубины и количества узлов. Сложность JSON-оболочки ограничена отдельно с учётом того, что типизированные значения разворачиваются в контейнеры и пары полей. Проверка периодически отдаёт управление для отмены.

Файл сначала ограничивается по размеру, читается как строгий UTF-8 и JSON. Некорректные UTF-8/JSON и неподдерживаемая версия останавливают сценарий до чтения текущих файловых хранилищ. Внутренние raw-строки сохраняются как в экспорте: повреждённый внутренний JSON отмечается предупреждением, а не молча заменяется. Известные строковые настройки темы, учётки и видов не выдают ложное предупреждение о JSON.

Вычисляется SHA-256 выбранного файла через Web Crypto. При недоступности API показана понятная ошибка. Архив не подписан: отпечаток без доверенного эталона не подтверждает автора, подлинность и отсутствие изменений до проверки. UI явно сохраняет это ограничение.

3. СРАВНЕНИЕ С БРАУЗЕРОМ
Оркестрация выделена в сервис с зависимостями чтения. Авторизация выполняется до чтения файла, после проверки архива и перед выдачей результата; проверяются актуальный настройщик, доступ, ревизия и выбранная учётная запись. Сервис не получает методов записи localStorage и использует прежний адаптер readonly IndexedDB, без создающих/мигрирующих репозиториев.

localStorage сравнивается по исходному ключу и точной raw-строке. Различие порядка/оформления внутреннего JSON тоже считается различием строки, не семантическим изменением отдельного студента.

В файловых хранилищах сравниваются первичные ключи и типизированное содержимое записи, включая scope/владельца, двоичные байты, MIME и File-метаданные. Порядок свойств объекта не создаёт ложного конфликта; порядок массивов и тип значения сохраняют значение. Версии/наличие баз, keyPath, индексы и структура хранилищ показываются отдельно. Текущие записи без архивного аналога не читают двоичные байты только ради статуса «Только в браузере».

Числа обозначают локальные документы/файловые записи, а не количество студентов внутри документов. Отчёт возвращает только итоги, ID различий и предупреждения, без всего JSON/Blob. Ошибка чтения любого текущего источника не выдаёт пустое успешное сравнение. В конце повторно сверяются localStorage, состав/версии баз и доступ.

Проверка не является общей транзакцией всех источников. Изменения содержимого IndexedDB между независимыми чтениями и возврат к прежнему состоянию могут не обнаруживаться. Отчёт помечен временем; дальнейшее применение потребует повторной проверки. Отдельный origin/basePath архива отмечается предупреждением о совпадениях ID разных установок.

4. ЧТО ЕЩЁ НЕ ПРОВЕРЯЕТСЯ
Внутренние версии и бизнес-схемы raw-документов, учебные связи, ссылки вложений, соответствие inline keyPath значению, уникальные индексы при записи, доступность настройщика после восстановления, миграции и корректность генераторов ключей остаются отдельной задачей. Успешная структурная проверка не даёт разрешения на восстановление.

JSON.parse не обнаруживает повторные имена членов внутри исходного JSON-объекта; после разбора проверяются явные списки ключей и типизированные пары. При проектировании подписанного формата и применения нужно определить канонический формат/парсер и проверку целостности, не считать этот этап готовым импортом.

Лимиты сравнения текущих источников остаются ограниченными. Для больших объёмов и потокового формата требуется отдельный этап. Личная выгрузка пользователя также не реализована и не подменяется административным архивом.

5. ПРОВЕРКИ
87 тестов в 8 файлах: существующие экспорт/IndexedDB/значения/страница и новые localBackupValidation, localBackupInspectionService, InspectionPanel.
Покрыты реальный круг export → File → validation → comparison, точный отпечаток, сохранение исходных источников, совпадающие ID с различающимися байтами, перестановка свойств, текущие записи без архивного аналога, различия схем, строгий UTF-8, пустой/большой/повреждённый файл, несовместимая версия, дубли, неверный base64, несходящиеся итоги, ограничения, отмена и отзыв доступа на разных этапах, недоступный Web Crypto и отсутствие частичного результата после ошибки чтения.

UI-проверки выполнялись через серверную разметку: подпись выбора файла, состояние занятости/отмены, сообщения, пагинация, экранирование имён/ID, отсутствие фиктивного восстановления. Это не эмуляция взаимодействия в настоящем браузере. Полный набор всех тестов приложения не запускался.

TypeScript, общий ESLint и production-сборка /BIUniversity/ с native-загрузчиком конфигурации прошли. check:build: 95 записей manifest, 120 файлов, начальный JS — 4 файла, 519 958 байт / 166 165 байт gzip; статических циклов и зависимостей vendor от страниц не найдено. Отслеживаемый кэш TypeScript возвращён в исходное состояние. diff --check без ошибок; проверены 52 хэша исходного архива, 7 активных планов, 33 Markdown-ссылки и 7 заключительных пересказов.

Computer Use, браузер, CDP, Playwright и окна пользователя не использовались. Реальные файловые диалоги, загрузки, память на больших файлах, браузерная отмена, темы и клавиатурная приёмка остаются открытыми.

КРАТКИЙ ПЕРЕСКАЗ
Настройщик может локально проверить свой административный архив и увидеть различия с браузером без записи. Повреждённые и несовместимые файлы отклоняются, различия содержимого и структуры не скрываются. Применение восстановления, бизнес-валидация, личная выгрузка и реальная браузерная приёмка остаются в плане.
