# Преподаватель · вторая вкладка «Расписание» (`/schedule`)

Read-only аудит исходников: `frontend/src/pages/schedule`, `ScheduleWeek` (включая список и сведения о занятии), `Filters`, `SearchField`, `WeekPicker`, `ScheduleCard` и непосредственно используемых ими стилей. Это выводы по коду, **не** результаты просмотра интерфейса в браузере. Приоритеты: P0 — блокирует понятную навигацию/доступность; P1 — существенно усложняет сценарий; P2 — улучшение ясности. Другие вкладки не анализировались.

## P0

1. **Переход между учебными годами заблокирован обычной навигацией.** `frontend/src/components/WeekPicker/index.tsx`: `weeks` строится только для учебного года `getAcademicYearBounds(endOfWeek(currentDate))`; `minWeek`/`maxWeek` ограничивают `changeWeek`, кнопки «Предыдущая неделя»/«Следующая неделя» становятся `disabled` на краях. В результате преподаватель не может стрелкой перейти с последней недели июля к следующему учебному году и с первой недели сентября к предыдущему: открыть иной год можно лишь через внешний `?date=` или возврат к текущему. Дать явный переключатель учебного года либо разрешить стрелкам переходить через границу, пересчитывая `weeks` по новой дате; диапазон показывать рядом с выбранной неделей. Переиспользовать существующий `WeekPicker` и `Dropdown`, не добавлять второй календарь. Проверить август/сентябрь, июль/август и прямую ссылку с `?date=`.

2. **Ошибка поиска не привязана к полю.** `frontend/src/components/Filters/index.tsx`: `submit` при пустой строке устанавливает `error`, но `SearchField` получает только `label`, `value`, `onChange`; сообщение `<p className={styles.error} role="alert">` не связано с `<input type="search">` из `frontend/src/components/SearchField/index.tsx`. После объявления alert при повторном попадании в поле нет ни `aria-invalid`, ни `aria-describedby`; ошибку приходится искать визуально. Расширить переиспользуемый `SearchField` опциональными `error`/`description` и связать ID сообщения с инпутом; при неуспешном submit перемещать фокус в поле. Сохранить текущее сбрасывание ошибки при изменении строки/типа. Селекторы: `.inputRow input`, `.error` в `Filters/index.module.scss`.

## P1

3. **Неверная подсказка в пустом личном расписании.** `frontend/src/components/ScheduleWeek/index.tsx`: при `!lessons.length` заголовок различает `filtered`, но одинаковый текст «Выберите другую неделю или измените запрос поиска» показывается и для `filtered={false}`; в личном расписании (`frontend/src/pages/schedule/index.tsx`, `selectedSchedule === null`) запроса нет. Разделить тексты: личное — «Выберите другую неделю» (при необходимости действие поиска); найденное по запросу — «Выберите другую неделю или измените поиск» с кнопкой открытия панели. Переиспользовать существующие `WeekPicker` и переключатель поиска `.searchToggle`; не отправлять к несуществующему запросу.

4. **Список перегружен пустыми парами даже для насыщенной недели.** `frontend/src/components/ScheduleWeek/WeekList/index.tsx`: для каждого из шести дней вызывается `getScheduleDayRows(events, DEMO_SCHEDULE_SLOTS)`; `frontend/src/data/scheduleSlots.ts` содержит семь слотов, а `EmptySlot` выводит «Нет занятий» для каждого свободного слота. Это до 42 строк-заглушек за неделю, дополнительно к кнопкам перехода по дням; занятия и пересечения теряются в шуме и длинной прокрутке. По умолчанию показывать занятия и компактный итог свободного дня; добавить управляемый режим «Показать все пары» для тех, кому важны окна и номера. Переиспользовать `WeekList`, `EmptySlot` и существующий счётчик `.daySummary`, сохранить явную пометку пересечения/нестандартного времени. Селекторы: `.rows`, `.slotRow`, `.emptySlot` в `WeekList/index.module.scss`.

5. **Прокрутка сетки плохо обнаруживается.** `frontend/src/components/ScheduleWeek/index.module.scss`: `.scroller { overflow: auto; scrollbar-width: none; }` и `.scroller::-webkit-scrollbar { display: none }` скрывают и горизонтальный, и вертикальный индикатор, хотя максимальная высота `min(720px, 72dvh)` и ширина дня не менее 200px; в JSX `ScheduleWeek/index.tsx` есть стрелки для горизонтального перемещения и текстовая инструкция, но нет видимого признака вертикально скрытых пар. Оставить видимую тонкую полосу прокрутки и/или постоянный индикатор переполнения, особенно при выборе «Сетка» и на узком экране; проверить мышь, тач и клавиатуру. Переиспользовать существующие `.gridTools` и `.scroller`, не вводить параллельную прокрутку страницы.

6. **Поиск на узком экране может сжимать названия типов до непонятных кнопок.** `frontend/src/components/Filters/index.tsx`: три подписи «Группа», «Аудитория», «Преподаватель» остаются в одном `role="group"`; `Filters/index.module.scss` при `max-width: 650px` задаёт `.types { flex: 1 }`, `.types > button { flex: 1 1 auto; padding-inline: 7px; font-size: 12px }`, а `.header` в той же строке содержит кнопку закрытия шириной 40px. На очень узкой ширине группа переносится по кнопкам или переполняет шапку, нарушая читаемый порядок. Перестроить `.header` так, чтобы закрытие было отдельным элементом, а типы — полноширинным сегментом с допустимым переносом/вертикальным вариантом и читаемыми подписями. Переиспользовать `Filters` и групповые кнопки из `_switches.scss`; проверить ширину 320px и масштаб текста 200%.

7. **В плотной сетке исчезают важные атрибуты пары.** `frontend/src/components/ScheduleWeek/index.tsx`: при `lanes > 1` передаётся `compact`, при `cardHeight < 44` — `short`; `frontend/src/components/ScheduleCard/index.module.scss` скрывает `.type`, `.info`, `.footer` в `.grid.compact`, а в `.grid.short` ещё и `.top`, где указано время. Полная информация остаётся в `aria-label`/`title` и модальном окне, но для зрячего пользователя с тачем `title` не помогает и короткие одинаковые предметы трудно различить. Добавить доступное без hover краткое время/аудиторию или заметный признак «ещё сведения» в компактном тайле; при экстремальном уплотнении предложить перейти к списку. Переиспользовать `ScheduleCard` и уже существующий переключатель `.views` (`ScheduleWeek/index.module.scss`), не уменьшать шрифт бесконечно.

## P2

8. **Диапазон недели на рубеже лет неоднозначен.** `frontend/src/components/WeekPicker/index.tsx`, `formatDateRange`: год берётся только из `endDate` и добавляется в конце. Например, диапазон декабрь–январь показывает только год января, хотя начало относится к предыдущему. При разных годах печатать год у обеих дат, при одном — один раз; оставить русскую локаль и вариант для одной/разных месяцев. Переиспользовать текущий форматтер `WeekPicker` и существующий `Dropdown`, без отдельного компонента даты.

9. **Текст для экранного диктора обещает переключение дней, а действие только прокручивает.** `frontend/src/components/ScheduleWeek/index.tsx`: `aria-label` области `.scroller` — «Стрелки влево и вправо переключают дни», тогда как `onGridKey` вызывает `move()`/`scrollBy()` и не выбирает день; кнопки `.gridTools` также прокручивают на `dayWidth`. Исправить формулировку на «прокручивают сетку по дням», согласовать её с видимой инструкцией. Переиспользовать уже существующую подпись области `role="region"` и кнопки навигации.
