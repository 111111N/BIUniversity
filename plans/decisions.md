# Согласованные решения

Актуализировано 28 октября 2026 года. Эти ограничения действуют при выполнении планов и не означают повторную реализацию уже существующих функций.

## Модель и данные

- Три типа учёток: студент, преподаватель, настройщик. Расширение ролей сейчас не входит в объём MVP.
- Номер зачетки состоит из года формирования, одной цифры корпуса от 1 до 9 и четырёх цифр последовательности: `YYYYCNNNN`, например `202630001`. Номер показывается перед созданием, недоступен для изменения и сохраняется при последующих учебных операциях.
- Обучение и доступ к входу — отдельные состояния. Блокировка входа не делает учащегося выпускником или отчисленным.
- Группу нельзя архивировать, пока в ней есть учащиеся; действующие проверки других зависимостей также сохраняются.
- Учебные события допускаются за сегодня и прошедшие дни, по действующим правилам хронологии. Будущие события не входят в текущий объём.
- Раздельные преподаватели лекций, практик и лабораторных — открытая задача U03, её нельзя потерять при изменении учебной модели.
- Стабильные ID, зачетки, история, отметки, попытки ответов и владельцы файлов сохраняются при миграциях. Перевод не переносит старые оценки в новую учебную область.
- Сброс пароля пока только интерфейсный. Настоящий вход, отправка и сброс пароля относятся к отдельному серверному этапу; не показывать фиктивное успешное выполнение.
- Локальная версия остаётся демонстрационной. Сервер должен самостоятельно проверять автора, права, версии, уникальность и целостность данных.

## Интерфейс

- Не добавлять дублирующие заголовки «Расписание» и «Планировщик» внутри этих вкладок. Неделя остаётся основным верхним ориентиром.
- Обычное расписание показывает понедельник–субботу; воскресных пар нет. Полосы прокрутки сетки скрыты. Планировщик не ограничен учебными днями.
- WeekPicker общий для расписания и планировщика. В планировщике «Создать» стоит перед «Неделя / Список», карточки близки к стилю мессенджера.
- Общие переключатели сохраняют принятый образец заданий; активные блоки — согласованный красный акцент. Использовать токены тем и непрозрачные поверхности всплывающих окон.
- Новые поиски имеют видимые подписи и пустые placeholder. Для больших справочников нужны поиск и ограниченная выдача, а не стена кнопок.
- Главная студента близка к преподавательской: поиск/расписание слева, задачи «Что требует внимания» справа, показатели отдельным широким блоком. Поиск студента по умолчанию — по аудитории, преподавателя — по группе. Прежнее оформление кнопок поиска на главной сохраняется.
- Окно расписания главной имеет высоту 300 px, длинный день прокручивается внутри; ссылка следующего учебного дня закреплена внизу, без показа его пар и баннера о свободном дне.
- Материалы студента: сначала «Группа», затем «Общее»; по умолчанию «Группа». При смене области действует защита очереди файлов.
- Формулы показателей, дедлайны, видимость и права не меняются под видом стилизации. Новый UI не должен выдавать локальный черновик за серверное сохранение.

## Рабочий процесс

- Продолжать работу с кодом без Computer Use, браузера и управления окнами пользователя до изменения этой просьбы. Непроведённую визуальную приёмку сохранять открытой.
- Новые библиотеки и внешние сервисы требуют отдельного согласования. Не добавлять их только ради реализации идеи из плана.
- Коммиты, отправка в Git и публикация выполняются по отдельной команде пользователя. Обновление планов само по себе их не запускает.
