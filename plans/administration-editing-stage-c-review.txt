ПАНЕЛЬ НАСТРОЙЩИКА: КАРТОЧКИ УЧЁТОК, ГРУПП И ДИСЦИПЛИН
27 октября 2026

ОБЛАСТЬ РАБОТЫ
Продолжение этапа C из administration-editing-ui-ux-plan.txt: единый каркас редактирования, разделение областей учётки, сохранение контекста реестра и выбор большого числа групп. Это изменение интерфейса и состояния форм; новые роли, правила доступа и форматы хранения не вводились.

ОБЩИЙ КАРКАС
RecordEditor используется для учётки, реквизитов группы, создания дисциплины и назначений преподавателя. Сверху находятся название записи, контекст, состояние правок и возврат к списку. Поля отделены от реестра. Снизу — одна область с отменой и конкретным действием сохранения.
Возврат и отмена вызывают существующий requestAction: изменённая форма не закрывается в обход защиты несохранённого ввода. Во время записи кнопки закрытия/отмены недоступны. На телефоне действия переносятся; фиксированная область поверх полей не добавлялась.
Панели непрозрачные, текст и кнопки используют общие токены обеих тем. Нативные поля на узком экране имеют шрифт 16 px. Длинные названия переносятся, области формы имеют min-width: 0.

УЧЁТНЫЕ ЗАПИСИ
Открытая карточка скрывает фильтры и список. Поиск, тип, статус, группа и страница остаются в URL; реестр сохраняется в DOM с hidden и не участвует в Tab. После закрытия восстанавливается фокус исходного действия; если запись исчезла из текущей выдачи, используется начало списка.
«Данные» содержат личные реквизиты: имя, логин и почту. Группа, состояние обучения и зачетка перенесены в «Обучение». Учебное событие с датой и основанием появляется при соответствующем изменении группы/состояния; используются прежние проверки хронологии и команды.
У преподавателя появилась область «Назначения» со сводкой и переходом в дисциплины с выбранным преподавателем. У настройщика нет неприменимых учебных областей.
В «Доступе» находятся блокировка/восстановление, интерфейс сброса пароля и действие «Изменить тип». Отдельная равноправная вкладка «Тип» убрана. Старая ссылка mode=role поддерживается и открывает ту же защищённую операцию в области доступа. Неприменимые mode для другого типа учётки приводят к «Данным».
Создание сохраняет выбор типа, группы, корпуса и предпросмотр неизменяемого номера. Выдача номера существующему студенту находится в «Обучении»; ссылка из проверки данных обновлена на эту область. Сохранение обучения не требует выдавать номер, если он ещё не был выдан: сохранено прежнее разделение команд изменения данных и выдачи зачетки.
У неизменённой новой формы с заранее выбранной группой больше нет ложного признака правок: сравнивается начальное состояние, а не наличие заполненных системой полей. Реальные изменения по-прежнему защищены.
Если редактируемая учётка пропала, обновление карточки не открывает создание вместо неё. Текущий ввод остаётся в форме, выводится понятная ошибка. Смена вкладки заблокирована на время записи.
Сброс пароля остаётся интерфейсом без сервера авторизации. Новая авторизация не реализовывалась.

ГРУППЫ
Создание и редактирование реквизитов используют общий каркас; над формой больше нет конкурирующей кнопки создания другой группы.
В карточке состава оставлены основные действия добавления студента и редактирования. Импорт, расписание и архив/восстановление находятся в «Ещё действия». Предпросмотр зависимостей и запрет архива при учащихся студентах сохранены.
Открытие группы из реестра теперь сохраняет q/campus/status/page. Возврат «Все группы» восстанавливает этот срез, не перенося в него поиск студента, историческую дату и страницы состава. После создания новой группы контекст общего списка тоже сохраняется.
При закрытии формы реквизитов фокус возвращается к доступному действию в карточке; при создании — к исходной кнопке, если она ещё существует.

ДИСЦИПЛИНЫ И НАЗНАЧЕНИЯ
При открытой форме скрываются поиск дисциплины, создание другой записи и список преподавателей. Сохранённый запрос и страница реестра не сбрасываются. Возврат из формы восстанавливает исходное действие и разрешает браузеру прокрутить его в видимую область.
При фиксированном преподавателе вместо поискового списка с одним вариантом показываются имя и логин. В контексте преподавателя действие «Все преподаватели» переименовано в «Сменить преподавателя»; оно использует прежний переход с защитой ввода.
Выбранные группы выводятся по шесть, поиск работает по всему выбору. Вложенная прокрутка списка выбранных групп убрана. Счётчик и пагинация показывают размер выбора.
Поисковый запрос доступных групп теперь учитывается массовым действием: «Добавить найденные (N)». Без запроса доступно явно названное «Выбрать все доступные (N)»; N означает число добавляемых групп. «Снять все (N)» обозначает масштаб снятия.
Массовое добавление объединяет выбранное с найденным, не теряя недоступные/архивные ID. Имена таких групп берутся из каталога, архив обозначается; если записи больше нет, выводится понятное состояние с ID. Снятие остаётся явным действием пользователя, а допустимость записи повторно проверяется прежним сервисом.
До сохранения видны количества «Добавится» и «Снимется». Подробности раскрываются с поиском и выдачей по восемь строк. В подтверждении снятия используется тот же просмотр вместо длинного абзаца названий. Назначения по остальным дисциплинам не переписываются.

АРХИТЕКТУРА
RecordEditor содержит только каркас и кнопки. AccountFields отвечает за состав полей разных областей учётки. Разрешение mode, состояние выбора, разница назначений и восстановление параметров списка вынесены в отдельные функции представления.
Учетные записи, учебные события, номера, группы и назначения записываются прежними accountService/groupCatalogService/subjectCatalogService. Серверные контракты и границы команд не менялись. Новых библиотек нет.

ГРАНИЦЫ ПРИЁМКИ
Живой осмотр браузера в этом проходе не проводился: предыдущие попытки Computer Use остановились из-за невозможности надёжно определить URL окна Chrome. Новых скриншотов нет; реальный фокус, Tab, мобильная клавиатура и итоговый вид в темах пока не подтверждены.
Автоматические проверки состава полей и чистых функций не заменяют браузерный сценарий. Смена типа и учебного состояния проверяются также существующими тестами команд, но реальные клики по новым областям требуют отдельной приёмки.

АВТОМАТИЧЕСКИЕ ПРОВЕРКИ
Полный Vitest: 88 файлов, 544 теста прошли. Добавлены 13 проверок областей учётки, состава полей, старых mode-ссылок, контекста списка групп, выбора из 100 групп, сохранения недоступных выбранных ID и разницы назначений.
TypeScript и ESLint изменённых TS/TSX-файлов с --quiet прошли. Финальная npm run build -- --configLoader native завершилась успешно вместе с tsc -b; Vite оставляет предупреждение об основном чанке 517,28 кБ.
git diff --check не нашёл ошибок пробелов. Предупреждения LF/CRLF относятся к настройке окончаний строк. Реальные клики, фокус и внешний вид не подтверждались этими проверками.

КРАТКИЙ ПЕРЕСКАЗ
Редактирование отделено от реестров и оформлено одинаково. Учебные данные студента больше не смешаны с личными реквизитами и доступом. Большой выбор групп получил поиск, страницы, явное массовое добавление и просмотр разницы. Права, история, номера и правила записи сохраняются; живая визуальная приёмка ещё открыта.
